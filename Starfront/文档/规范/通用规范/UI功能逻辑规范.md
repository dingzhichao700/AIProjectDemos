# UI 功能逻辑规范

> 适用范围：基于本模板开发的 Unity uGUI 窗口绑定类与功能逻辑代码。

UIBinder 可见绑定与运行时解析、跨平台输入和舞台尺寸响应，统一遵循 [运行时框架与加载规范.md](运行时框架与加载规范.md)，不得以旧类名回退掩盖空绑定。

### UIBinder Inspector 搜索绑定

- 绑定列表上方提供横向搜索输入框和“清空”按钮，按绑定 GameObject 的节点名称实时进行连续子串匹配，忽略大小写及搜索文本首尾空格；空文本显示全部。
- 显示匹配数与总数，无匹配时提示“没有匹配的绑定节点”。搜索文本只保存在 Inspector 实例中，不写入组件或 Prefab。
- 点击清空或切换选择时重置搜索；普通 Inspector 重绘不清空。选择事件订阅随 Inspector 启用、停用成对管理。
- 搜索只过滤显示，保留原始列表索引和绑定编号；新增编号仍根据完整列表计算，删除定位原始条目。一键生成绑定及相关同步始终使用完整列表。

## 微信运行时文本输入（2026-11-12 用户确认）

本节是游戏运行时输入框的平台键盘与焦点契约；不适用于Unity编辑器Inspector搜索框。新建、修改或迁移微信端可编辑输入框时必须执行。GM参数提交的专门要求见[GM开发调试模块规范](GM开发调试模块规范.md#gm-parameter-submission)。

1. **显式接入**：必须确认所用SDK、目标平台和输入组件的实际键盘路径；不能把`TMP_InputField`可选中、桌面能输入、`TouchScreenKeyboard`设置或预制字段存在当作微信能弹输入法的证明。SDK关闭Unity默认移动键盘时，输入框必须通过平台适配器接入微信原生键盘；不得让业务页各写一套SDK监听，也不得未经评估修改SDK或全局键盘开关来掩盖缺失的适配。
2. **实现与分层**：Main正式内容界面复用`PlatformInputFieldKeyboard.Install(input)`及`ITextKeyboard`/`WeChatTextKeyboard`；动态列表在实际单元绑定后安装，普通表单在控件就绪后安装。重复安装不得增加组件或监听。其他程序集的界面通过其允许引用的平台提供器实现同一契约，Login/Foundation不得为复用Main组件而反向依赖Main。Editor及非微信平台保留其正常输入路径。
3. **文本与提交**：平台Input回调必须同步可见文字并触发当前字段应有的值更新；执行/保存前必须取得最终平台文本与当前字段快照，不依赖“最后一次值改变事件一定先于点击”的时序假设。绑定身份、参数序号和来源必须仍属于当前表单，不能把池化控件的旧值提交给新对象。各表单明确Confirm、Complete、取消与业务提交的映射；Confirm后Complete不得导致二次提交，Complete不得无条件触发业务操作。
4. **焦点与生命周期**：同时只允许一个活跃原生键盘会话；同次Select/PointerClick不重复打开。切换字段、失焦、字段隐藏/禁用、列表重绑/回收、父窗口关闭及销毁时，必须释放本会话的SDK监听并结束输入。先让会话令牌/版本失效，再隐藏键盘，防止同步Complete或迟到回调修改旧/新字段或执行业务；不得清除其他模块监听。
5. **异常与可用性**：只读、禁用或不可交互字段不唤起键盘。打开失败必须显示可理解的原因并留下可定位日志，不能假装获得输入；键盘状态和取消本身不得修改道具、等级或存档。
6. **交付检查**：列出静态字段、动态列表模板、运行时实例及跨界面消费点；核对安装路径、重复绑定、平台分支和生命周期，不以一个GM输入框通过代替其他表单通过。存量窗口发现缺口须登记实际归属、使用场景及迁移触发条件；未迁移项不得记为全项目已适配，新建/修改界面不得继续遗漏。
7. **验收**：专项先用隔离数据验证首次打开、编辑/清空、最终一次Input后立即执行、同次Select/Click、字段切换、Confirm→Complete仅一次、取消、关闭/重开、回收重绑、迟到回调和打开失败；桌面输入必须回归。模拟器、目标平台编译、发布校验与真机验收分别记录。发布后核对实际Base/Content，在目标手机确认键盘可输入、字段值与提交一致；涉及持久数据时核对实际增量、界面刷新及重启保持，禁止改真实存档伪造成功。

**当前实现与边界**：WECHAT-GM-INPUT-R1已接入GM参数，34项隔离自测及WebGL目标编译通过，用户已确认手机输入法、碎片增加和重启数量正常；[版本与验收记录](../../交接/微信GM输入与碎片反馈修复-2026-11-12.md)。该结论不覆盖其他表单。`LayerEffectTestPanel`的6个存量开发字段现已按INPUT-LEGACY-6-R1完成适配，77项Editor实际入口/射线与原生回调模拟、WebGL目标编译及场景恢复检查通过；其中四个网格字段在隔离的保留通用分支验证，正式场景预览模式保持。该增量已随Content 20261112T103416677Z（同Base 20261112T081217448Z）发布、用户已独立确认可见颜色字段手机键盘弹出、颜色修改生效及关闭窗口收起键盘通过；四隐藏网格字段仍仅Editor验证，不扩大真机结论；[迁移与验证边界](../../交接/存量六输入框适配与自测-2026-11-12.md)。后续新输入框仍须逐项接入及验收，不回写外部模板。

## BasePanel 窗口规范

1. UI 作为窗口使用时，对应的绑定类必须继承 `BasePanel`。
2. 每个 `BasePanel` 子类必须声明构造函数，并在构造函数中设置 `layer`。具体窗口层级根据页面替换、覆盖关系和交互需求选择，不固定套用某个层级。
3. 每个 `BasePanel` 子类必须覆写 `OnOpen()` 和 `OnClose()`，即使当前没有额外逻辑也保留生命周期入口。
4. 界面需要接收键盘操作时，必须覆写 `OnPanelOperate(PanelOperateEnum operateCode)`，并根据 `PanelOperateEnum` 将操作分发到对应响应逻辑。
5. 窗口需要注册消息或交互监听时，通常在 `OnOpen()` 中调用私有函数 `AddLis()`，并在 `OnClose()` 中调用私有函数 `RemoveLis()`。注册与注销必须一入一出、严格成对。

`AddLis` 和 `RemoveLis` 是项目约定命名，不替换为其他同义名称。

### 窗口统一开关表现

状态：现行。2026-11-06用户确认已接入效果通过，并要求后续新增非全屏窗口统一使用本标准。本节为当前项目窗口过渡的单一来源。

1. **接入范围**：现有及后续新增的非全屏独立窗口必须显式声明 `UsesWindowTransition => true`，复用 `BasePanel` 与 `PanelWindowMotion`，禁止遗漏接入或另写一套不同参数的过渡。全屏界面采用同步开关，统一过渡保持关闭；常驻HUD不按弹窗处理。`UsesFullScreenViewport`仅表示舞台适配，不能据此判断窗口类型。窗口分类与内容节点在开发前明确。
2. **已确认参数**：打开时内容从最终显示位置上方10设计像素下移归位，透明度0→1，时长0.24秒、OutQuad减速曲线；关闭时内容上移10设计像素，透明度1→0，时长0.18秒、InQuad加速曲线。位移与透明度使用相同曲线和时长，不增加缩放、弹跳或错峰。10像素随界面整体适配缩放。
3. **内容与遮罩**：通过 `WindowTransitionContent`指定内容节点；未指定时，由公共实现于 `SafeContentRoot`下建立独立内容容器。不得直接移动被安全区组件持续定位的容器。存在遮罩时，通过 `WindowTransitionMask`明确指定；遮罩只同步淡入淡出，最大透明度沿用原设计，不随内容移动。
4. **生命周期**：通过 `OnPrepareOpen()`准备打开参数、内容数据及布局，随后播放表现；`OnOpen()`与`OnPostOpen()`在打开完成后调用。交互监听在`OnOpen()`注册、`OnClose()`注销，必须成对。关闭表现完成后才调用`OnClose()`并进入复用池。
5. **交互与复用**：动画期间拦截内容操作；关闭期间保持遮挡直至退场完成。重复关闭仅执行一次；打开中关闭须取消旧动画，避免迟到的打开回调。复用前恢复正确位置与透明度，不累计位移或残留动画。应使用公共实现处理这些行为。
6. **新增窗口验收**：检查首次打开的数据与最终位置、10像素位移及透明度、内容/遮罩分工、动画期间输入拦截、关闭完成后回收、连续开关不漂移、重复关闭和打开中途关闭。全屏界面检查同步开关及未启用统一过渡。运行验证与用户视觉确认分别记录。

已接入并由用户确认效果通过的窗口为队伍编辑、技能详情、设置、通用确认和GM。五类窗口的重复开关、打开中断及MainPanel同步开关隔离验证通过；本次确认不扩大为真机或发布验收。

替代关系：本节将先前的已接入说明整合为强制接入标准；早期打开0.18秒/关闭0.12秒试验参数及设置窗口原分段入场退出方案不再作为新增窗口依据。

## C# 换行风格

使用 K&R 风格：类、函数、条件和 `switch` 的左花括号与声明位于同一行。

人工编写的 `if`、`else`、`for`、`foreach`、`while`、`do` 等控制语句必须使用花括号，执行体独立换行；即使执行体只有 `return`、`continue` 或 `break`，也不得压缩成单行。

人为维护的 C# 代码中，函数、构造函数和委托调用的完整参数列表必须写在同一物理行；函数或构造函数的声明参数列表也必须写在同一物理行。UIBinder 自动生成区域、第三方代码和其他机器生成文件保持各自生成格式。

```csharp
public class ExamplePanel : BasePanel {
    public ExamplePanel() {
        layer = PanelLayer.SCALE_PANEL_SECOND;
    }

    public override void OnOpen() {
        AddLis();
    }

    public override void OnClose() {
        RemoveLis();
    }

    private void AddLis() {
    }

    private void RemoveLis() {
    }

    public override void OnPanelOperate(PanelOperateEnum operateCode) {
        switch (operateCode) {
            case PanelOperateEnum.ESC:
                Close();
                break;
        }
    }
}
```

UIBinder 自动生成的成员区域继续由工程既有生成器维护，不为其中的成员声明添加人工注释；功能逻辑写在生成标记区域之外。

## 底板承载型UI的可摆放视觉区域（2026-11-12 用户确认）

确认依据：用户“这类元素的摆放也需要规范，首先就是：根据底板图片的视觉特征，确立可摆放视觉元素的范围。”适用于由可见底板承载图标、艺术字、文本、数字等元素的复合UI，例如战力栏、货币栏、属性牌和数字徽标；独立图标的语义锚点规则保持。

1. **先定底板可摆放区，再排内容。** 根据真实底板图片的视觉特征，识别内容承载面、内沿、描边、金属斜面、剪角、装饰件和发光边缘；据此划定允许放置图标/文字/数字的区域与需避让区域。PNG全画布、Sprite矩形、RectTransform、透明BBox及一条像素采样中线均不能自动充当可摆放区。
2. **区域先有可复现几何。** 记录底板资源/版本、源尺寸、实际显示矩形与缩放、允许区域的矩形或多边形、禁入区域、对齐参考线及边距含义。不规则承载面保留真实剪角/曲面特征，不为方便统一成整张矩形；多个承载面分别登记。无明确依据的边距或区域参数标为候选，不从现有控件坐标反向宣称已批准。
3. **在区域内再分配元素。** 先确定各元素的子区域、排列顺序、对齐和间距，再落实为RectTransform。衡量实际可见图形/字形及约定的阴影、光晕，区分资源画布、Image矩形和主体边界；不能只让图片框排齐，忽略透明留白导致的主体偏移。测量使用的Alpha阈值和含/不含特效范围必须说明。 Unity Image的实际网格还受Pivot、preserveAspect、Sprite裁切/padding及像素对齐影响；源PNG投射或控件矩形不能代替最终可视像素，关键对齐应以独立渲染Alpha或经独立验证的等价证据复核，不用同一推算公式同时生成预期与验证结论。已有Pivot/语义锚点未经授权不改，不以裁掉描边或拉伸素材掩盖不匹配。
4. **先交区域示意。** 第一次确立底板区域时，展示同一底板上的“可摆放区／避让区／参考线”，再展示元素落位；线框与装配读取同一组参数，提供原尺寸与注明倍率的局部证据。按项目现有设计验证流程审核；已批准区域直接复用，不能每次换字或换数值重新猜一套。具体资源参数由对应专属规范维护。
5. **变体与复用。** 同类组件复用同一份区域定义；宿主底板视觉几何有真实差异时，登记对应区域变体，不能仅复制坐标或随手等比缩放内容后称已对齐。换底板或改变拉伸方式后，先复核区域，再复核各消费端；区域确认不等于元素摆放、最终美术或运行效果已通过。

本节为底板上视觉元素摆放方法的单一来源。图标内容的开口/遮罩按《框体与内容类美术资源制作规范》处理；承载文字/数字的区域不因此自动变成图标遮罩。示意交付按《示意图交付与比例核验规范》执行。

## 图片对齐与列表预览

1. uGUI 图片默认使用矩形区域对齐作为实现方式；有可见底板时，先按上节确定可摆放视觉区域，再对齐元素的可见主体，不能把图片矩形中心自动当作底板或主体的视觉中心。资源集合明确声明为锚点对齐时，使用方在图片加载完成后同步 Sprite Pivot，并保持业务定义的语义锚点坐标固定；切换资源时不得对坐标进行 Pivot 补偿。
2. 对可能需要锚点对齐的可替换系列资源，应按需要提示使用者确认对齐模式；不得由实现者逐张猜测。
3. ScrollList 中保留的编辑器预览项不得命名为 `{Template}(Clone)`，该命名只用于运行时实例，避免预览项被对象池误收。
4. 货币、评级、资源消耗等正式语义图标优先使用独立 `Image`，不依赖特殊字体字符模拟。
5. UI 交付前检查实际文本的 TMP 字形覆盖。静态字库缺字时补齐字形或配置合适的回退字体，不接受缺字方框作为完成状态。

## 数字徽标与共用组件核验（2026-11-11 用户确认）

- 费用等数字徽标拆成共用底图与独立动态文本；同一设计对象在不同位置复用同一组件及已确认显示尺寸，不以分别摆放相似图片代替复用。
- 要求数字居中的徽标，以底图约定可见圆心/中心为目标，文本按可见字形几何中心对齐；文本框使用统一中心锚点/Pivot及明确边距，禁止针对具体数值逐个手调偏移。字体透明留白、行高及投影不等于数字主体边界；若底图可见圆心偏离画布中心，先修正或明确底图锚点，不靠随数值变化的偏移掩盖。
- TMP可采用水平、垂直Geometry对齐；验证应检查实际可见字符几何边界，并结合目标尺寸实拍。不能直接以RectTransform中心、字体行高或未核实语义的textBounds证明可见数字居中；具体API含义以工程所用版本为准。此约束只适用于要求居中的数字徽标，不替代名称、等级等已确认左/右对齐规则。
- 使用当前配置代表值、一位/两位/三位数字及缺值符号核验；检查单行、溢出、投影与裁切。多位数适配策略须明确，不以换行掩盖空间不足，也不把测试值写回业务配置。
- 修改共用组件后，列出全部消费入口与实例覆盖项；按各入口及不同装配方式核验引用、尺寸、状态和运行时覆盖，确认修改实际传播。未执行的入口如实记录，不以一个实例通过代替全引用通过。
- 校验失败时保留原结果及定位结论；测量指标错误须修正指标并重新执行，不放宽阈值或删除断言冒充通过。程序测量、视觉自检与用户验收分别记录；局部证据按[示意图交付与比例核验规范](示意图交付与比例核验规范.md)执行。

## 通用组件状态与异步生命周期

1. 禁用按钮的默认灰化只调整 RGB，保留原 Alpha；灰化强度允许按组件配置。
2. 可销毁、回收或复用的组件发起异步加载时，应使用请求版本或等价机制废弃过期回调，并在回调前确认对象、请求版本和目标资源仍有效。

## C# 注释规范

1. 类注释使用多行 `/// <summary>` 简述角色，并以 `/// <remarks>` 说明职责范围。带参数且逻辑复杂的函数也使用 `/// <summary>`，参数或返回值语义不直观时补充 `param`、`returns`。
2. 变量、属性和简单函数使用单行 `/**注释内容*/`，不使用单行 XML 注释。
3. 生命周期、状态转换、异步回调、资源加载、对象池复用、数值计算和跨界面流程等关键逻辑，必须说明设计意图、前置条件或副作用。注释重点回答“为什么这样处理”，不得逐行复述代码。
4. Demo 中暂时代替正式配置系统的常量或规则，必须在所属类型或配置入口注明未来替换来源，例如 Luban；不要求为每个同类常量重复注释。
5. 本节注释与换行风格只约束人为撰写和维护的代码。UIBinder 自动生成区域、第三方代码及其他机器维护区域保持各自生成格式，不得为了人工代码风格修改生成器或整理其内部成员。
6. 人为代码中显而易见的赋值和监听注册不强制注释，避免制造注释噪音。
7. 人为代码的类左花括号后、类右花括号前至少保留一个空行；变量、属性和函数之间至少保留一个空行。人工代码与自动生成区域交界处保留一个空行即可。
8. 修改功能逻辑后的检查必须包含：人为代码的注释类型是否符合成员复杂度、关键状态和异步边界是否有意图注释、成员间空行是否完整、已有注释是否仍与代码一致。过期注释按缺陷处理。

## C# 类型文件组织

- 每个业务模块使用独立目录 `com/game/{module}/`，同一模块的入口、数据、常量和视图代码均收纳在该目录下，不按单个界面拆成多个代码模块。
- 一个文件只定义一个同名顶层类型，不得在主要 Panel、View、Control 或 Model 文件前后附加包外类、枚举或结构体；仅属于主类型实现细节的嵌套类型可以保留在类内部。
- 拆分或迁移 Unity 源文件时必须连同 `.meta` 一起移动以保持 GUID；整理过程不得顺带改变类型名称、访问级别、序列化关系或运行时行为。
- 模块代码按职责组织：`view/` 只存放 Panel、View、Item 等视图类；`model/` 存放业务数据管理类；`model/vo/` 统一存放各种 `{Semantic}VO.cs` 数据对象；`constant/` 存放静态常量类和静态工具类。
- 作为模块对外入口且采用单例访问的 `{Module}Control` 或 `{Semantic}Control` 直接放在模块根目录，不再增加 `control/` 目录；普通内部控制类不因名称带 `Control` 自动提升为模块入口。
- 模块仅在存在业务数据管理需要时建立与模块同名的 `{Module}Model`，不得为了满足目录形式机械创建 Model；数据管理职责过大时，可以按明确业务职责增加其他 Model。
- 数据对象命名为 `{Semantic}VO`，其中 `VO` 表示 Value Object，不得用 `{Semantic}Model` 表示单条数据对象；模块内的 VO 文件统一放入 `model/vo/`。
- 模块存在 `{Module}Model` 时，模块入口 `{Module}Control` 必须通过只读属性 `model` 暴露其实例，统一使用 `{Module}Control.ins.model` 访问模块数据。`Control` 负责业务流程，`Model` 负责数据集合、查询、初始化与存储边界。
- `View` 负责显示与输入，可以通过 `{Module}Control.ins.model` 读取展示数据；数据修改、状态推进及其他业务动作应调用 `Control` 的业务方法，不得由 `View` 直接修改 `VO`。
- 原型阶段用于代替正式配置系统的静态配置类放入 `constant/`，并在类注释中标明未来配置来源；不得把大型配置类附加在 Panel 或其他 View 文件中。


## 程序集分层的路径适配

## UI文本组件与投影（2026-11-05确认）

- 游戏UI文本统一使用TextMesh Pro（uGUI使用TextMeshProUGUI），采用项目已有字体与字库，不以Legacy Text、烘焙文字图片或系统预览字体替代。
- 当前游戏界面字效以字面加右下方深色投影对齐参考，使用TMP SDF材质的Underlay；默认关闭Outline且Outline Width为0，不用一圈均匀描边代替投影。
- 复用字体时使用兼容同一字体图集的材质预设，分别管理字色、投影颜色/透明度、偏移和柔化；不得为单一窗口直接修改全局字体默认材质。字体fallback与图集引用须兼容。
- 审核图中的像素投影仅作参考，TMP Underlay参数不是屏幕像素，接入后须在目标显示尺寸核对字面粗细、投影方向和裁切。各界面的素材、结构、实际运行图及用户审核分别按对应专项交接记录，不以规范文字替代验收。

全局非交互滚动提示属于独立表现宿主，不使用普通窗口开关过渡，也不参与窗口键盘焦点选择。异星军团的样式、层级与调用契约见[全局滚动提示规范](../专属规范/全局滚动提示规范.md)。
