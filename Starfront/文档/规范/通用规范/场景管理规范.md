# 场景管理规范

> 适用范围：需要持续模拟场景元素，并将逻辑状态同步到 Unity 表现层的游戏模块。

## 一、逻辑元素与唯一数据真相

- 所有场景逻辑元素统一继承 `SceneElementVO`，创建时必须明确指定 `TimerType`。
- `SceneElementVO` 只保存逻辑坐标、朝向、生命周期和玩法状态，禁止持有 `GameObject`、`Transform`、`RectTransform`、`Image` 等表现对象。
- SceneModel 负责场景元素的登记、移除、查询和时间推进，是场景状态的唯一数据真相。
- 场景元素使用稳定唯一 ID；逻辑层与表现层仅通过该 ID 建立临时映射。
- View 不得反向决定碰撞、伤害、死亡、销毁或其他权威逻辑结果。

## 二、Timer 驱动

- 场景逻辑禁止直接读取 `Time.deltaTime`，统一使用所属 Timer 发出的时间更新。
- Timer 更新回调传递经过自身 `scale` 处理后的秒数。
- 玩家及其衍生元素使用 `playerTimer`，敌方及其衍生元素使用 `enemyTimer`，中立或其他场景元素使用 `sceneTimer`。
- UI 动画等非场景内容默认使用通用 Timer。
- SceneModel 对每种场景 Timer 只订阅一次，再向对应元素集合分发；不得让大量元素分别注册 Timer 回调。
- 模块关闭或场景销毁时必须取消 Timer 监听，避免残留更新。

## 三、逻辑常驻与视窗同步

- 元素只要在逻辑上存在，即使位于玩家视窗外，也必须继续推进逻辑。
- 表现层只同步视窗内元素；元素进入视窗时创建或恢复 View，离开视窗时停止同步并按需回收 View。
- 回收 View 不等于销毁逻辑元素；只有 SceneModel 的权威逻辑可以结束元素生命周期。
- 逻辑与表现分离主要降低耦合和表现开销；需要降低逻辑开销时，应另行引入空间索引、分级或低频更新策略。

## 四、模块职责

- Panel 只负责界面生命周期、输入转发、HUD 和表现层入口，不承担完整场景模拟。
- Model 管理权威状态和场景元素集合；Control 负责场景流程和对外操作入口。
- 资源依赖收集、碰撞计算、对象池等职责应按需拆成独立类，不得长期堆积在 Panel。
- 每个重要运行对象使用独立类文件，不在 Panel 文件前后定义大量包外类。

## 五、资源与系统边界

- 进入场景前应从入口配置递归收集可预知的实体、子弹、特效等资源依赖，去重后统一预加载；缺失依赖应在进入场景前报错。
- 依赖收集器只遍历配置并生成资源清单，不执行加载或玩法逻辑。
- 碰撞系统只检测并返回碰撞事实；Model 应用伤害、死亡等权威结果；表现层只消费结果并播放反馈。

## 六、生命周期与对象池

- Timer 和事件监听必须成对注册与注销；模块关闭时清理异步回调、表现对象和所持有的池化对象。
- 池化 View 再次使用前必须重置全部可变表现状态，不得继承上次生命周期的坐标、旋转、显隐、透明度或动画状态。
- View 回收和逻辑销毁必须分别定义，禁止以回收表现对象替代结束逻辑生命周期。

## 七、临时测试与重构验收

- 临时数值、跳过流程等测试覆盖必须集中标识；恢复正式配置时同步恢复相关测试断言。
- 提交前核对临时配置、调试入口和测试预期，不得通过删除失败断言掩盖状态不一致。
- 重构验收关注权威逻辑归属、依赖方向和冗余对象是否消除，不以文件数量或代码行数作为完成依据。
- 架构调整后至少执行顶层类型检查、编译和代表性流程验证。

## 八、验收

- 场景逻辑代码中不存在 `Time.deltaTime` 直读。
- SceneModel 开关流程能够正确订阅和取消三类场景 Timer。
- 视窗外元素持续运行，回到视窗后表现能够同步到最新逻辑状态。
- 逻辑对象中不存在 Unity 表现对象引用。
- 仅移动目录、拆分文件或建立空 Model，不视为完成逻辑与表现分离。

## 九、战斗场景界面与 LOD 层

确认日期：2026-10-19。本节是场景节点分工及跟随信息归属的规范来源。

### 界面分工与节点结构

- 战斗场景界面负责场景内容及跟随场景对象的平面信息；独立信息界面负责头像、倒计时、货币余额等固定 HUD。
- 场景容器内设置场景内容层和叠加其上的 LOD 层。此处“LOD 层”指本项目的视窗内平面信息显示层，不据此推导网格简化或其他渲染 LOD 机制。

~~~text
战斗场景界面
└─ 场景容器
   ├─ 场景内容层：地块、建筑、移动单位等
   └─ LOD层：血条、生产进度环、伤害飘字等
~~~

### 配置与定位

- 场景尺寸、格子布局等从配置表读取，不在界面中硬编码。现有示意图参数属于当前地图配置参考，不替代运行时配置读取。
- LOD 层仅显示视窗范围内相关对象的平面信息，按稳定对象 ID 绑定所属对象及其信息锚点。
- 对象移动或镜头拖动时，将对象锚点转换到 LOD 层坐标并同步位置，保证两层对齐；不要同时重复应用镜头位移。
- 血条、进度环、伤害飘字独立于建筑/单位图像，不烘焙进实体素材。

### 生命周期与逻辑边界

- 对象离开视窗只隐藏或回收表现节点，生产、移动和战斗等业务逻辑继续运行；重新进入视窗时显示当前状态，不能从旧进度重新开始。
- 对象销毁时清理关联的持续显示节点；伤害飘字等短时效果按自身生命周期结束，不能因回收导致悬空引用。
- 界面关闭时清理本层关联及监听，池化节点复用时重置绑定对象、锚点、进度和显隐状态。
- 进度、血量和伤害来自业务逻辑；LOD 层只展示，不负责生产计时、货币发放、单位生成或伤害结算。

### 己方生产进度环

| 建筑 | 展示的生产周期 |
|---|---|
| 基地 | 自动定时产出局内货币 |
| 资源采集站 | 自动定时产出局内货币 |
| 船坞（兵营） | 自动定时产出对应作战单位 |

- 仅显示己方生产进度；敌方建筑、炮台、废墟和空建造内容不显示生产进度环。
- 圆环按当前生产进度更新，产出后重置并进入下一周期；建筑被摧毁后移除。
- 生产进度环明确归属战斗场景界面内部的 LOD 层，不归属独立信息界面。此前聊天中“属于信息界面层”的表述以本节为准。
- 圆环具体美术尺寸、颜色与偏移尚待设计确认，本节只确定归属与显示行为。
