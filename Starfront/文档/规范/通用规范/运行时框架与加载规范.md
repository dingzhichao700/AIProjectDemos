# 运行时框架与加载规范

> 适用范围：模板及其派生工程的通用框架。平台专属策略以对应平台规范为准；微信小游戏遵循 [微信小游戏平台规范.md](微信小游戏平台规范.md)。本文规定应保持的行为，实现与验收状态见 [平台配置与模板验证.md](平台配置与模板验证.md)。

## 一、程序集及职责边界

- Foundation 管理计时、资源、对象池、UI 基础设施、持久化基础服务与模块装载，不引用 Login、Main 或具体业务模块。
- Login 管理登录阶段；Main 管理进入游戏必需的核心业务。Login 不得编译依赖尚未装载的 Main，通过底座提供的模块入口契约请求进入正式内容。
- 仅在存在实际业务时新增 SubModule；不得预先创建空程序集。跨模块公共代码先明确归属，不为消除引用错误把业务 UI 塞进 Foundation。
- 设置数据的读取与基础设置应用可以属于底座，设置界面属于业务。核心服务先就绪，再应用本地设置，最后启动业务入口；已有设置和首次生成的设置均须正确应用。
- `.asmdef` 定义编译边界，不等于热更新开关。Editor 工具隔离到编辑器程序集；每个程序集显式声明自身直接使用的依赖，如 TMP、DOTween 模块和 Addressables，不能借其他程序集的引用替代自己的引用。
- 新模板采用 `Assets/Scripts/csharp/foundation`、`login`、`main` 分层。业务模块在所属程序集目录内继续按 view、model、model/vo、constant 等职责组织。旧 `com/core`、`com/game` 路径是迁移来源，不能与新分层混用为两套权威规则；迁移须保持 Unity GUID 和序列化引用。

## 二、分阶段及异步加载

- 每个阶段明确进入条件、必需代码与资源、成功出口和失败行为；预加载范围不能仅凭 Group 名推断，须检查 Prefab、字体、图集、共享控件等间接依赖。
- 无依赖关系的资源允许有限并行；有依赖的初始化保持顺序。批次并发上限显式指定，不能无限创建任务，也不把 Task 并发误称为 Unity API 多线程执行。
- 批次失败后停止领取新项，等待已启动任务收尾后反馈异常；不得在部分失败时报告全部完成。帧动画就绪包括帧数据准备完成，不能只以 PNG、JSON 下载完成判定。
- 同一资源或模块的并发请求合并，失败后清理进行中状态并允许重试；已经成功装载的业务程序集不能重复装载。
- Unity 对象创建、Sprite 操作、UI 更新保持在主线程。需摊帧的工作使用真正的下一渲染帧等待，不用同一 Update 中反复出队冒充摊帧。
- 界面关闭、销毁或池化复用后，旧异步结果必须失效；使用请求版本或等价机制防止结果写入新实例状态。
- 加载诊断使用不受游戏 Timer 倍率影响的实际耗时，记录阶段、版本、成功或失败，并区分下载、反序列化、对象创建及演出等待。资源项数进度不等于下载字节进度。
- 演出与资源预加载可同时进行；进入下一阶段前分别确认演出条件与资源条件。演出时长属于产品设计，禁止为“优化加载”擅自删掉，也不把某个样例的演出秒数固化为模板常量。

## 三、Timer 调度与回调

- Timer 的累计时间和延迟参数使用毫秒；逐帧监听接收已经过倍率处理的秒数。调用者必须明确单位，不重复应用倍率。
- 连续动画、运动按所属 Timer 的逐帧时间推进；避免短间隔 Loop 轮询造成帧率量化。Timer 的通用 Loop 每轮最多执行一次，不补跑错过的历史间隔；需要补偿的算法自行根据累计时间计算。
- 调度使用可线性遍历的活动集合，字典负责查询索引；禁止在热点循环中对字典反复 `Keys.ElementAt`。高频回调使用类型化委托，不通过 `DynamicInvoke` 执行。
- 同轮到期任务按注册顺序执行。调度回调内新增或覆盖的普通任务下一轮参与；零延迟 Once 保持立即执行。CallLater 回调中再次排入的任务下一轮执行。
- 取消即时阻止后续执行，遍历结束后统一整理和回收；不得在回调尚未结束时复用其 Handler。Clear 取消同一调用者全部匹配回调，包括 CallLater。
- 逐帧监听派发期间新增的监听者不参加当前派发，移除操作不破坏遍历。单个回调异常须记录并隔离；同一 Timer 不允许重入 SyncTime。
- Handler 回收清空调用者、回调、执行器与参数；对象池有容量上限。销毁的 Unity 对象必须按 Unity 空值语义识别，模块退出仍须主动注销监听。
- 时间倍率为零表示游戏时间不推进，不代表暂停全部系统任务、异步下载或 CallLater；不得依靠游戏暂停阻止初始化流程。
- 修改调度语义时运行相关回归检查，覆盖取消、新增、覆盖、空参数、异常、重入、销毁对象及池化引用清理；源码测试不能替代真机性能验收。

## 四、帧动画与共享图集

- 帧通过 `Sprite.Create` 引用原图集纹理的矩形区域；不得为每帧新建 Texture2D 或复制像素。创建 Sprite 不等于创建新纹理。
- 默认由根节点保留动画原始画布、Pivot 和业务变换，显示子节点表达裁剪区域及偏移；采用等价的单Image等显示实现时，也必须满足下文的锚点与裁剪显示契约。Trim、翻转、缩放和旋转后必须保持原始位置语义。未支持的旋转打包帧应显式报错，不能错误播放。
- Sprite 仍在使用时必须持有源图集及资源句柄。失败时销毁本次已创建的 Sprite 并释放所持句柄；将来增加卸载机制时，须先结束全部使用再释放共享资源，不能在帧生成成功后释放源图集。
- 生成任务共享每渲染帧软预算，跨动画共同限流；预算不保证单次 Unity API 调用可中断。当前样例约 2ms 是已验证的起点，调整须结合设备实测。
- 播放按累计时间选帧，循环保留超出时长的余数；帧索引不变时不重复刷新 Sprite 和布局。一次性动画完成后停止监听，可按调用契约保留末帧或回收。
- 一次性特效优先使用对象池。回收清理播放监听、完成回调、父节点及异步请求状态；超出池容量或明确永久释放时才销毁。
- 共享图集减少纹理对象、CPU 像素复制及上传，不保证图集总显存一定更小。当前样例尚未实现按使用者引用计数卸载、池预热及帧索引查找优化，不把这些写成已交付能力。

### 帧动画锚点与裁剪显示契约

状态：现行。确认日期：2026-10-26。适用于单位、特效及其他自定义帧动画显示入口，不仅限于左右镜像。

1. **区分数据语义**：动画级pivot表示完整原始画布中的语义锚点；sourceSize表示该帧裁剪前画布尺寸；frameOffset表示裁剪区域相对完整画布的偏移。区域Sprite自身的pivot可能仅为加载器内部设置（例如零pivot），禁止直接把它解释成角色落脚点或特效定位点。数据缺失或无法解释时显式报错，不静默改用左下角、图片中心或包围框底部。
2. **统一坐标后计算**：必须明确pivot是归一化坐标还是像素坐标，以及Y轴方向；进入显示计算前统一为同一画布坐标系。以左下角为原点、尺寸和偏移均为像素、动画pivot归一化时，`裁剪区域锚点像素 = sourceSize × 动画pivot − frameOffset`，乘法按分量执行；单Image实现的RectTransform pivot为该值除以裁剪区域尺寸。若源JSON偏移使用左上角坐标，先按完整画布高度、裁剪区域高度转换，不能直接相减。裁剪区域中的语义锚点允许位于可见区域之外，不得钳制到区域边缘。
3. **围绕语义锚点变换**：换帧、换朝向、翻转、缩放或旋转后，业务定义的逻辑锚点位置保持不变。镜像围绕该锚点执行；不得再按图片宽度或pivot差值补偿业务位置，避免重复修正。裁剪偏移应还原图像在原画布内的位置，不能当作额外的逻辑位移。
4. **显示与剔除一致**：绘制、镜像及视窗剔除使用同一份定位结果；包围框由实际帧尺寸、还原后的锚点及变换计算，不能仍按零pivot或未镜像区域计算。验证人物仍可见时不会提前回收，离屏恢复后显示当前帧与当前逻辑位置。
5. **统一使用定位契约**：优先复用已有帧动画显示组件及定位计算。需要自定义显示入口时，先检查加载器输出与现有显示链路，复用计算或通过等价实现验证；不得仅取得Sprite后绕过原画布、pivot和裁剪信息。文档约定不表示已经提供新的共享定位API，不为满足文档机械增加一套组件。
6. **池化完整恢复**：回收时清理Sprite引用、播放监听、完成回调及异步请求；再次使用前按新资源完整恢复pivot、原画布/裁剪尺寸、帧偏移、缩放、镜像、旋转、透明度、帧索引与播放时间。不能只替换Sprite，或继承上一方向、上一角色的状态。
7. **分开验收**：运行时正确使用锚点，与源素材锚点本身准确，分别记录结论。运行验证覆盖全部实际方向与帧、左右镜像、换朝向、裁剪边界变化、非居中锚点、视窗进出及池化复用；用实际变换后的语义锚点与逻辑定位点比对，并核对画面。资源脚底校准须按资产规范审核代表帧和动作连续性，不能用数学对齐通过代替美术落点确认。

本次补充只明确原有原画布、裁剪和镜像规则，不改变共享纹理/句柄生命周期。具体画布尺寸、帧数及暂用pivot属于资产记录，不提升为通用常量；项目实现验收与模板/工具链迁移状态分别记录。

## 五、UI 绑定与跨平台交互

- UIBinder 的编辑器脚本选择与运行时类型标识来自同一份有效绑定；空绑定、脚本已删除、类型不存在或成员不匹配必须明确报错，禁止用旧类名静默兜底。
- 编辑器负责将所选脚本解析为可用于运行时的类型标识；运行时不依赖 UnityEditor.MonoScript。类型解析支持命名空间及程序集，相关业务 DLL 必须先装载再创建界面。
- 迁移、改名时同时检查脚本 GUID、Inspector 绑定、序列化类型标识及成员导出；不得仅以运行时还能打开界面判定绑定正确。
- 键盘、鼠标和触摸共用同一操作入口，不复制业务分支，不得触发一次输入却执行两次操作。移动端可操作性纳入对应平台验收。
- 舞台响应实际视窗变化，按界面策略选择全屏或等比容纳，保持设计空间与输入坐标转换一致，不统一锁定舞台长宽比；设计尺寸、安全区及平台遮挡遵循[UI视窗与安全区适配规范](UI视窗与安全区适配规范.md)。仅初始化时读取屏幕尺寸不构成自适应，Editor与真机分别验收。

## 六、回写与验收边界

- 仅回写已验收的通用实现及必要依赖；保留模板原有有效 GUID，新增源文件配套元文件。不得复制样例业务资源、项目专属地址或生成缓存。
- 文档规则生效与实现迁移完成分别记录。模板实现回写需检查调用链、序列化兼容及原有功能，不机械覆盖整个样例目录。
- 通用框架回写运行模板静态验证、相关源码回归及隔离工程 Unity 编译；影响资源引用时验证 Addressables 和缺失引用，涉及平台行为时增加对应平台运行验收。

## 七、资源业务约定与基础层边界（2026-10-28）

状态：现行；依据用户确认，本次落地 Starfront，未同步外部模板。

- Foundation 负责资源加载/缓存、UI 工厂/池、音频播放与帧动画显示。项目资源目录、清单、窗口路径、音效 ID 和默认材质选择不得写入该层。
- Login 的 ResourceConst、AudioConst、GameResourcePresentationPolicy 管理项目资源约定；LoginEntry 在读取设置和打开任何界面前，通过 ResourcePresentation.Install 安装策略。缺少策略显式报错。编辑器独立预览由 ResourcePresentationEditorSetup 安装同一策略，不替代运行时入口。
- IResourcePresentationPolicy 是 Foundation 定义的稳定契约，由热更新层实现；Foundation 不引用 Login/Main。策略随启动安装，同进程不用于切换资源版本或替换已加载程序集。后续业务新增资源不得通过扩充 Foundation 的业务枚举/列表实现。
- Login 的 UIEnum 管理启动窗口与共享 Main 入口标识；MainUIEnum 管理 Main 自有窗口。窗口标识和完整资源地址分离，由策略解析地址，原有标识值保持兼容。
- 图片支持 ImageResource（完整 Address、ResType、图集 SpriteName），Foundation 不再按路径目录猜测资源类型。旧 string 接口仅调用业务策略转换；非约定目录资源可直接提供明确描述。
- BasePanel.KeepOpenOnCloseAll 决定批量关闭时是否保留；LoadingPanel 覆盖为 true，PanelMgr 不特判窗口名。
- 按钮保留既有序列化 ButtonSoundType 值，由热更新策略映射音效；AudioManager 不负责业务 ID 规则。当前项目按音效 ID 查地址仍为空占位，本次保持原行为，不代表音效资源已补齐。
- 帧动画播放时由策略提供默认 Material（null 表示 Unity UI 默认材质），回收/重置清空材质，复用时重新取值。选择非默认材质时，业务预加载须先保证材质资源就绪；材质资源由资源管理器持有，View 不销毁共享材质。
- 框架接口、AOT 实现及平台启动能力变化仍需评估并重建底座；普通窗口、路径、音效映射和默认材质约定变化可随热更新业务发布。此轮基础接口/类型归属已变化，下一次发布必须生成新底座，并重新生成匹配的 HybridCLR 桥接/AOT 产物，不兼容混用旧 DLL。

验收依据见《基础层资源约定迁移-2026-10-28》；编辑器通过不替代微信真机验证。
