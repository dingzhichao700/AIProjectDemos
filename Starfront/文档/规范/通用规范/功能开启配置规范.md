# 功能开启配置规范

适用范围：采用本表结构的项目。具体业务记录由项目维护，不因规范归入通用目录而自动成为模板数据。源表、生成与加载统一遵循[配置表工具链规范](配置表工具链规范.md)和[游戏业务与配置规范](游戏业务与配置规范.md)。

整理日期：2026-10-21。本文区分填写约定与已实现能力；校验要求不代表已有自动校验工具。

## 字段与条件

- `FunctionResource`：`id` 为唯一功能标识，`name` 为显示名称，`openCondition` 为 `FunctionOpenCondition` 多态 Bean 列表。
- 空列表直接开启；非空列表全部条件满足才开启（AND）。不使用字符串表达式，不隐式支持 OR。
- `PlayerLevelCondition.level`：玩家等级达到指定等级。
- `MissionProgressCondition.missionIndex`：已通关指定关卡，仅解锁或到达不算。
- `DisabledCondition`：别名“暂未开放”，无参数，条件恒不满足。
- 新条件需同步 Bean 定义、判断逻辑、提示文本及校验；不能只增加配置后默认放行。

## 边界与校验

- 功能条件由统一业务入口判断，View 只展示状态和调用接口，不维护另一套条件判断。
- 未知功能 ID 或条件类型应明确失败；条件依赖的权威数据未就绪时，不虚构进度或放行。
- 检查 ID 唯一性、Bean 类型及参数有效性、关卡引用和提示覆盖。验证空列表、多条件部分满足/全部满足、暂未开放及未知条件。
- 永久解锁还是动态锁定、存档位置、入口隐藏还是显示，由项目明确，不强制所有项目采用同一策略。
- Starfront 的永久解锁、导航提示、具体功能及接口见[项目功能开启配置规范](../专属规范/功能开启配置规范.md)。
