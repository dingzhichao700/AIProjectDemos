# 构建与发布职责规范

- 标准化样例工程的构建发布统一由 `game-build-release` Skill 维护；当前落地微信小游戏适配，其他平台按需增加，不能套用微信策略。
- 模板生成、源码回写由 `game-framework-toolchain` 负责；构建队列适配器保留在工程内，共用调度及发布校验位于构建发布 Skill。
- 项目参数使用 `ProjectSettings/FrameworkPlatform.json`；不在通用脚本内写死项目名、CDN、AppID。生成工程的 `Tools/Build-WeChatHotUpdate.ps1` 只转发到已安装 Skill。
- 构建/发布范围、项目隔离、不可变资源校验、指针切换顺序、历史保留及分层验收流程，以构建发布 Skill 的通用规范和对应存储适配流程为权威来源，项目不另行维护上传步骤。
- 底座与内容兼容性、启动入口和客户端缓存协议见 [微信小游戏平台规范](微信小游戏平台规范.md)；修改协议时同时核对客户端与构建发布工具。
- 工程根目录不擅自新增目录，产物及验证资料使用已有 build/Tools 约定。构建不隐含提交业务源码或清理历史资源。
- 当前以对话调用 Skill 运行，无需 Jenkins。完整执行契约以已安装 `game-build-release/references/构建发布规范.md` 为唯一维护源。

## 配置、环境与验收记录归属

- AppID、桶、地域、项目目录、入口地址等实例值以 `Project/ProjectSettings/FrameworkPlatform.json` 为权威来源，不作为通用规范示例写死。
- COSCLI 及其依赖位置由 Skill 配套第三方工具说明维护；真实凭证路径和本机调用说明留在工程外的本机环境说明。项目配置和验收记录均不得包含密钥。
- 机器可读交付记录使用 `build/wechat-delivery.json`，并同步对应 `build/archives/<底座版本>/delivery.json`；人工交接摘要保存在 `文档/交接/`，由规范索引引用。历史版本记录不能被最新状态覆盖。
- 验收结果只说明对应版本已经完成的验证，不自动成为新规则或其他平台的验证结论。

修订（2026-10-27）：依据用户确认的归属划分，将本文件中重复的发布操作条款改为 Skill 引用；补充配置、本机环境及验收记录职责。其余规则继续有效，未同步外部模板。

客户端底座核对、重启/换包交付及同底座热更新验收，统一按 game-build-release 的《构建发布规范》“客户端底座核对与真机交付”执行；运行版本展示见[GM开发调试模块规范](GM开发调试模块规范.md)。不得将换包验证写成同底座热更新通过。
