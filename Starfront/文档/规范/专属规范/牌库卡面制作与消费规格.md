# 牌库卡面制作与消费规格

版本：deck-card-face-spec-v7。状态：现行。2026-11-06用户批准将切角、斜面、分层及跨会话生产约束整合进卡牌配套资源规范；原156×189生产基准不变。本版替代v6的对应条款，历史资产批准范围不变。
范围：牌库卡面及其独立UI组合；不替代上阵立绘、战场单位、解锁卡或详情图的专项规格。

本篇是[卡牌配套资源规范](卡牌配套资源规范.md)下卡面生产参数与验收要求的唯一来源。发起、派发、接续、制作或消费CardImage前必须读取本篇，并在任务单锁定规范版本、批准主体及共用框体版本。不能只读配套总规范后直接生成整卡。

## 1. 当前基准与验收

- 视觉基准为用户指定的原卡组效果图，冻结证据：工作区outputs/card-reference-aligned-v1/source/user-ui-reference.png。
- 单元素提取与步兵组合获用户“完美”认可；156×189尺寸示意后获“看着还行，按这个规格继续生成吧”确认。证据：outputs/card-element-extraction-v1、outputs/card-dimensions-v1。
- 旋翼蜂鸟v2的局部构图与开放空中背景获用户“效果不错”认可，证据：outputs/hummingbird-card-face-sample-v2/visual-approval.json。人形与宽体样式已具备后续制作条件，但不自动批准其他单位。
- 2026-11-06用户“赞同”确认切角与分层规格示意，并以“按建议整理进规范”授权整合。[规格示意图](参考图/牌库卡面规格-v7.png)仅说明外接尺寸、切角/斜面及分层，不是生产遮罩或新框体批准；具体切角深度、斜面、高光和窗口轮廓以已批准素材及其实际Alpha为准。
- 本规范固化制作与审核口径；其余卡面、工程迁移、运行和真机分别验收。工作区批准记录不由资源会话擅自转成统筹公共gate。

## 2. 尺寸、坐标与显示分层

UI采用720×1280设计基准。原点左上、x向右/y向下，矩形记为[x,y,width,height]；参数取自已认可组合实际PNG/Alpha，而非从场景尺度推算。

| 项目 | 当前规格 | 说明 |
|---|---|---|
| 整卡及CardImage底图 | 156×189 PNG，sRGB | 图像覆盖整卡，信息底板作为独立UI覆盖下部；UI整体适配时等比缩放 |
| 制作工作画布 | 建议624×756或更高同宽高比 | 独立素材保留原生像素，不把放大工作层冒充原生分辨率 |
| 卡图窗口外接矩形 | [9,10,138,120] | 实际为品质框切角Alpha窗口；不能当矩形硬裁切 |
| 职能徽章底座 | [6,4,33,40] | 图标独立居中；没有职能映射时仅空底座，不自定类别 |
| 已上阵标签 | [39,113,78,19] | 空白平直标签+独立文字；置于卡图下沿，不用弧形飘带 |
| 名称 | 左侧x=12，基线y=153 | 与等级共用基线，不落在人物腿部 |
| 等级 | 右侧x=144，基线y=153 | 缺真实等级时明确占位 |
| 进度槽 | [12,160,132,22] | 槽、填充、数字分层；未知值不编造填充 |

头盔、面部、座舱及主要识别点避开徽章和状态标签，尽量距可见窗口边缘6px；其他装饰、肢体或载具部件可裁出窗口。个别宽体构图根据识别性审核，不为保全轮廓而缩成小图。

高分辨率提取件与显示尺寸分开。各元素保持纵横比缩放；以已确认框体真实Alpha生成窗口遮罩，防止卡图四角露框。不关闭preserveAspect或用非等比拉伸硬塞尺寸。

### 切角、斜面与图片遮罩

- 卡框四角采用斜切轮廓，并保留已批准素材的金属斜面、边缘高光和厚度；不能改为直角矩形、圆角矩形或只剩单根描边。框体为独立共用UI，不随每张CardImage重新生成。
- 矩形参数只记录外接边界。卡图按已批准品质框的实际内窗Alpha遮罩裁切，四角不得露图；不能把外接矩形直接当Mask，也不能照示意图多边形另造固定切角深度。
- 纯CardImage仍交付完整、不透明的主体＋背景PNG，切角由使用端遮罩与品质框组合实现；不能把品质框、切角黑底或状态文字烘焙到CardImage来掩盖漏角。
- 记录框体/遮罩资源ID、版本、来源哈希和拉伸方式。原生画布与156×189组合尺寸不一致时，只能使用对应已批准的派生、切片或等比装配方式，并记录参数；不得任意挤压已批准斜面与切角。
- 实际显示尺寸属于使用端。队伍编辑当前候选采用整卡0.9等比显示，是该窗口的布局记录，不成为卡面生产尺寸或其他用途默认比例。各用途需另记显示尺寸与批准状态。

## 3. 生产方法：分项提取，再组合

1. 从原参考逐项提取/修复品质框体、徽章底座、职能图标、空白状态标签、进度槽与填充。各自交付独立透明PNG，保留来源裁片与原始高分辨率结果。
2. 先核验单件轮廓、切角、材质与透明边缘，再用确定性缩放、定位及遮罩组合。禁止整张卡牌生图代替独立组件，不反复重绘已认可框体。
3. 角色/载具从对应原设定立绘直接抠图，保留原RGB和独立Alpha蒙版，不再生成或重画主体，不使用战场紧凑单位图冒充立绘。参考提取/遮挡修复的UI元素须明确工具与版本，不宣称生成式修复逐像素保真。
4. 背景缺失时单独生成，静态默认内置Image；不调用QWEN或读取其凭据。确定性处理不需要生图。
5. 品质框、徽章与图标、标签与状态文字、名称、等级、进度槽/填充/数字均为独立UI，不烘焙进CardImage。原参考颜色、职能及数字不自动成为业务配置。

当前独立提取件入口：outputs/card-element-extraction-v1。金色框仅为已确认样式，不代表所有单位被赋予同一业务品质；其他品质框确有需求时按原参考逐项提取并分别审核。

## 4. 主体构图与背景

- 人形/机甲使用头胸或头至腰部近景，突出头盔/面部、肩甲和代表性装备。以头部和躯干语义中轴居中，不按伸出的枪械总包围框居中，不强求全身入卡。
- 飞机/宽体载具使用足够有辨识度的局部近景，优先座舱、代表性涵道/旋翼、机鼻或机身连接区。允许远侧旋翼、机翼、车体与枪口末端裁出画面，不要求全机或双旋翼完整入框，不横向挤压主体。
- 统一种族视觉语言与光照方向，但按单位展示语境选择背景。步兵可用科技空间/机库；重装单位可用维护区；飞行单位可用开放空中港/天空。不得为复用而给所有单位套同一室内机库。
- 白橙装甲与深蓝/钢灰科幻环境保持可读对比；背景细节、亮度和对比弱于主体。背景不暗示未确认玩法，不烘焙品质色规则。
- 卡牌近景比例独立于战场体型与像素尺度，不能把战场尺寸或轴向视角直接套入牌库。

## 5. 交付与审核流程

按种族成套制作、集中预览，问题单位单修，保留不受影响的批准版本。首次建立制作标准时先人形、再宽体样件；两类均通过后展开其余单位。当前步兵与蜂鸟样式已认可，后续不得重复要求同范围确认。

每张必交：
1. 156×189、sRGB、不透明背景的纯card.png；不直接覆盖工程旧图。
2. 主体/背景/必要光效分层源及可复现裁切、缩放、定位参数；记录原生尺寸和实际可见边界。
3. 1:1干净图、适度放大检查、有/无上阵两态组件组合及同布局遮挡诊断。诊断只加辅助层，不更改排版来制造对齐。
4. manifest记录卡牌ID与artId的明确关联、规范版本、主体来源/版本/哈希、蒙版、背景提供方/版本、输出哈希、画布与关键点、用途配置、技术检查与人工审核状态。
5. 共用品质框、徽章、状态及信息底板交资源ID→版本→路径/哈希引用清单及装配参数；已批准共用件不逐卡重复生成。新建或修复的共用件单独交付和审核，不能借卡面获批扩大批准范围。

程序检查格式、尺寸、色彩空间、底图不透明、透明UI的Alpha、边界及引用完整性；用框体真实内窗遮罩检查四角无漏图、等比缩放后切角和斜面不变形，文字/状态与底图独立，并覆盖长名称和多位等级。用户审核构图、识别性、背景、金属质感及组合。组合视觉通过不替代运行、字体、加载或设备验收。

### 卡面生产任务单模板（由协调任务字段承载）

下表是卡面专项必填内容。统筹在现有任务JSON内按既有schema填入，再用`coord.py dispatch`生成任务单；本表不另创调度格式，Skill只引用本篇，不复制生产参数。

| 现有任务字段 | 卡面专项填写要求 |
|---|---|
| scope | 明确卡牌ID、artId、牌库用途、负责生产或仅使用端组合；列出不涉及的用途和实现 |
| inputs | 本规范版本及正式路径；批准主体/原设定立绘、框体及内窗遮罩的资源ID、版本、路径/哈希；批准证据；缺失项明确列出 |
| requires | 引用该任务实际需要的形象、框体或用途批准gate及版本，不以规范已更新代替资源已获批 |
| required_artifacts | 本节每张必交1—5项：纯card.png、分层源与处理参数、实际尺寸组合与同布局诊断、manifest、共用组件引用清单 |
| technical_checks | 按本节技术约束核验，并记录机器可查结果；切角/斜面外观另交人工审核，不用程序通过代替 |
| manual_review | 主体识别、参考一致性、切角/斜面/高光、遮挡、名称与等级、上阵两态及小尺寸表现 |
| stop_at / next_gate | 资源提交待审后停止；资源视觉、Figma结构、工程接入、运行和设备各层分记，按实际批准进入下一步 |

规范或共用框体更新时，仅对受影响卡面和消费端做差异复核。旧产物与批准证据保留，不自动失效全部资源，也不得未经复核将旧任务标成v7已通过。现有任务契约的调整由统筹按revision使用工具执行，使用端会话不改写他人任务或公共批准。

## 6. 配置与消费

- 牌库通过CardArtResource / CardArtObj.CardImage消费完整Addressables地址；CardArtImage.Usage.Card及消费端组件按显式美术ID关联读取。业务CardResource身份不得靠名称或目录猜测。
- 美术ID不代表持有、品质、上阵资格、兵种能力或生产行为。资源会话不新增这些业务数据；原参考数值不写配置。
- 上阵Formation保持透明与展示锚点契约；本规格背景、裁切和尺寸不推广到其他用途。本轮只补齐各单位CardImage，不默认重做其余用途。
- 原材料、候选、批准交付和运行资源分开。只有获得对应接入授权后再更新工程图片、Prefab窗口和配置，并复验缺图、列表复用、异步失效、关闭重开与释放。不自动构建发布。

当前10种用途与制作进度从工作区outputs/deck-card-face-spec-v2/resource-usage.json读取；该目录名是历史任务标识，不代表旧规格仍现行。上位用途矩阵见[卡牌配套资源规范](卡牌配套资源规范.md)，消费职责见[卡组界面资源引用规范](卡组界面资源引用规范.md)。

## 7. 替代与迁移边界

本版在v6基础上整合切角/斜面、真实Alpha遮罩、共用件引用与生产任务单要求；此前v2—v5已由v6整合。废止其作为现行制作要求的142×120透明主体、142×147内窗、156×207长卡、整机入框、大弧形横幅，以及直接整卡生图方式。旧尺寸仅可出现在历史产物或待迁移工程记录，不能继续作为生产模板。

此前源素材、批准/拒绝记录和工程资源不因文档更新删除或覆盖。当前批准样件位于工作区；工程接入须独立核验实际文件，不从规范改动推断已迁移。规范固化不等于工程同步；最新工程接入状态以文档交接记录为准。
