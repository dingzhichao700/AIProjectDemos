# 卡牌培养配置与查询接入规范

状态：结构及业务查询已实现，2026-11-05。用户授权先补配置结构与共用查询，缺少正式数据单列后再接界面。本篇不批准或补造数值，不扩展主动/被动技能的战斗执行能力。

## 1. 配置结构

全部通过正式ConfigResource/gen_json.bat生成，接入ConfigManifest与configData；当前34张表。下列结构已建立，内容完备性以当前正式导出及已确认交付为准；早期空表状态不作为当前结论。阶段现行来源见本篇“独立卡牌等级效果权威”；技能阶数与卡牌等级效果为不同数据域。

| 源表 | 键及数据职责 |
|---|---|
| CultivationRaceArtResource | race；background为培养背景资源地址。复用CardResource.Race |
| CultivationQualityArtResource | quality；podium为独立台座资源地址 |
| CardProfessionResource | cardId；profession为正式职业，不复用外观Tag |
| CardProfessionCounterResource | profession+targetProfession；关系清单，不含猜测倍率 |
| CultivationSkillResource | id为稳定培养技能ID；name/kind/slot/icon，独立于逐等级战斗技能ID |
| CardSkillEntryResource | cardId+skillId；sortOrder规定列表顺序，同序按稳定ID排序 |
| CardSkillRankResource | cardId+skillId+rank；unlockLevel、battleSkillId，引用该阶完整SkillResource效果 |
| CardGrowthStageResource | cardId+id；unlockLevel、description、sortOrder。2026-11-11恢复为独立卡牌等级效果的UI查询来源，正式表当前为空；不绑定技能 |

生成枚举：SkillKind仅Active/Passive；SkillDisplaySlot为Basic/Passive/Active/Ultimate；CardProfessionType为Vanguard/Firepower/Heavy/Support，对应先锋/火力/重装/支援。源表下拉使用中文别名并覆盖未来第5至1000行。沿用已有Race/Quality枚举，不另定义种族或品质。旧CardSkillSlot保留为④公开接口兼容标识，通过显式适配映射到生成的SkillDisplaySlot，不是另一份配置权威。

正式表不得写入未批准的示例数据；已批准陆战技能等按当前正式导出消费。资源字段为资源加载器可消费地址；未有正式统一目录前不臆造固定前缀。技能Icon为空会报告缺项，已有ItemResource.IconId=0同理。普攻/主动/大招都映射底层Active，被动映射Passive；无释放消耗字段。

技能rank必须从1连续，unlockLevel在1..卡牌上限内且随rank不递减；每阶引用真实SkillResource。卡牌等级达到条件自动解锁，只取最高已解锁阶，完整替换，不累加。尚无阶解锁时currentRank为null；没有阶数配置时unlocked也为null，不能显示为正常锁定技能。

CardCultivationConfigValidation.Validate(tables)校验枚举、底层/包装匹配、外键、重复关联/阶段、孤立阶数和等级边界；查询同时执行所需的局部检查。空表允许加载，由missing报告内容缺项。源表补齐后须再验完整数据和战斗执行的一致性，不能把本轮只读支持当成主动/被动战斗已经实现。

## 2. 公共查询接口

- `CardCultivationQuery.Read(Tables tables, PlayerProgressControl player, int cardId)`：在已有共享进度锁内读取成长、实际成本/余额、形象/背景/台座映射、职业/克制、属性比较、技能和阶段，返回CardCultivationStateVO。tables须为该player构造时使用的同版本配置。无业务写入或第二份存档。
- `CardSkillQuery.ReadAll(tables, cardId, cardLevel)`：按关联顺序返回技能列表。
- `CardSkillQuery.Read(tables, cardId, cardLevel, SkillDisplaySlot slot, int skillId=0)`：稳定技能身份、底层类别、正式图标地址、解锁状态、最高生效阶、完整各阶效果和missing。某包装存在多个技能而未指定skillId时显式拒绝，禁止擅取第一项。
- `CardSkillDetailQuery.Read(...)`：④原接口保留，内部委托CardSkillQuery，再适配为CardSkillDetailVO。现有OpenAsync/Close签名、Prefab、Binder、窗口布局和生命周期不变。

CardSkillDetailVO新增iconAddress/unlocked/currentRank。正式图标由现有表现资源消费端异步加载；查询不加载或持有Unity对象。原Sprite字段仍保留兼容现有弹窗，未擅自变更图标租用职责。

CardCultivationStateVO的growth直接来自CardGrowthStateVO；materials返回itemId/name/iconId/owned/required；attributes返回稳定key/name/unit及可空current/target；stages返回cardId/stageId稳定身份、条件等级、独立效果说明和gained；旧skillId/rank/skillName字段仅接口兼容且不赋值。缺失数值为null，不能转成0。材料查询完整保留全部成本；培养页超过3项时使用既有横向列表滚动展示，不报告三槽容量缺项、不截断或因容量拒绝提交。职业已配但无克制记录时仍报告语义缺项，不能把未填表解释成无克制。

属性比较的现有实现读取单位HP/移动速度、建筑HP/产兵间隔，以及唯一普攻射程/单次固定效果伤害。该普攻伤害字段不是独立攻击力，不能作为新属性设计的权威来源；当前培养页将basicDamage显示为“攻击力”属于待迁移差异。0级没有已有属性，1级仅作目标；满级没有下一档材料或目标属性。缺等级不按比例外推。

### 属性配置权威与关联约束（2026-11-06确认）

- 战斗与培养共用同一权威属性配置和业务查询；培养页只显示当前与目标等级的查询结果，不自算正式属性、技能结算或攻速间隔。
- 一张卡只关联1个作战单位和1个所属建筑。逐级记录可有多行，但同一卡牌不能在不同等级切换为不同单位或建筑。重复关联、多个对象或缺少应有对象均作为配置缺项/错误报告，不擅取第一项或合并。此为正式配置约束，不表示已完成源表迁移校验。
- 攻击力为独立单一属性；攻击速度同为单位属性，与移动速度分开。禁止从技能固定伤害反推攻击力，禁止将移动速度替作攻速。
- 普攻无释放消耗，默认100%技能伤害；攻速影响普攻释放间隔，统一引用[技能与自动普攻规范](技能与自动普攻规范.md)。具体公式与完整伤害结算未确定前保持缺项，不编造计算规则。
- 属性定义、卡牌对象关联及逐级属性结构按以上约束设计；后续替换basicDamage到独立攻击力查询。界面现有六项是当前布局，不构成属性全集或禁止后续配置攻击速度。


### 独立卡牌等级效果权威（2026-11-11用户修正）

- 卡牌升级到指定等级获得的效果与卡牌技能无关。2026-11-10“阶段从技能ranks投影”的裁决已被本节替代，不再读取技能名、阶数、技能解锁等级或技能伤害作为本区内容。
- 现有CardGrowthStageResource提供UI所需cardId、卡内id、unlockLevel、description、sortOrder。查询按unlockLevel/sortOrder/id排列，DTO稳定身份为cardId+stageId。未拥有卡不显示已获得，等级达到条件即gained=true；不新增领取动作或另一份存档状态。
- 正文仅独立效果说明，单行、不换行；保留已获得/未获得两态，不因只显示效果正文而删掉未来条目。当前UI查询只读说明，不执行或累加属性加成。
- 效果对象可以是本卡关联单位或建筑，通常修改属性。后续正式内容需明确等级、对象、属性ID、固定/百分比及增幅；现有description只是UI说明，不能据其文字解析或推断实际加成执行。数值结算与正式结构扩展另行按明确数据设计，本轮不编造。
- 用户本轮选择“暂不填正式数据，先完成排版和查询”。正式CardGrowthStage表保持空，空表不回退技能阶数；缺项报告为“卡牌独立等级效果未配置”。隔离记录只验证排序、等级状态与UI，不写入源表或ConfigBin。

1. 固定六项及分组：单位血量、攻击力、攻击范围、移动速度为上方四项；建筑血量、生产时间为底行两项。不增加攻速入口，不做自由属性列表。
