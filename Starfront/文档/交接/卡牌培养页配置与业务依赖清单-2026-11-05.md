# 卡牌培养页：配置与业务依赖清单

日期：2026-11-05。实施更新：用户随后授权补结构与查询，已完成部分以[现行配置与查询规范](../规范/专属规范/卡牌培养配置与查询接入规范.md)为准；下文保留实施前分析，不作为当前未实现状态判定。范围：③卡牌培养全屏界面及当前升级视图。依据：当前生成配置类、CardCollectionModel/Control、PlayerProgressControl、CardGrowthStateVO、CardSkillDetailQuery/VO及现行培养规范。本文为接入分析，不表示下列建议表名、字段或新增规则已获批准；不修改配置、业务代码或存档。

## 1. 按界面区域核对

| 界面区域 | 数据归属及已有来源 | 现状与需要补齐 | 界面职责 |
|---|---|---|---|
| 名称、品质、种族、上限 | CardResource：Name/Quality/Race/MaxLevel | 已有，复用；职业不能用TagId替代 | 读取展示，不重复存一份 |
| 单位形象 | CardResource.ArtId → CardArtResource.Portrait；CardArtImage | 复用已有批准资源及异步租用；逐卡核对资源批准范围 | 切卡取消旧请求，关闭释放，避免旧图覆盖新卡 |
| 三种族背景 | CardResource.Race + 展示资源映射 | 种族已有；需补三种族到培养背景资源的映射及正式资源，不从卡ID/文件名猜种族 | 随当前卡切换，全屏铺底，与safeContent分开 |
| 品质台座 | CardResource.Quality + 展示资源映射 | 需补品质到台座的映射和独立资源；已删除前置梯形铭牌 | 切卡更新，不烘焙在公共静态底板 |
| 职业、克制 | 正式职业定义及逐卡关联、克制规则/关系 | CardTagResource仅外观标签，不能充当职业；需要正式定义和对应数据。若克制涉及玩法，查询由业务管理，不由UI颜色推断 | 显示业务结果，缺项明确，不用参考图示例冒充 |
| 战力 | 统一业务计算或明确配置来源 | 尚需确定公式、输入范围及逐卡数据；不先发明权重或把示例19571写入配置 | 展示当前结果及必要增量 |
| 当前/下一等级与按钮 | CardCollectionModel.GetState → CardGrowthStateVO | 已有level/nextLevel/maxLevel/owned/maxed/canUpgrade/revision/unavailableReason/costs | 控制解锁、升级、满级、处理中显示；不自己计算资格 |
| 属性与升级变化 | CardUnitLevelResource、CardBuildingLevelResource、SkillResource及对应战斗配置 | 当前已有部分等级数据；需补完整卡牌/等级覆盖及统一只读比较结果。攻击可能来自技能效果，生产间隔来自建筑，不能强塞单位表或假设所有技能都是固定伤害 | 显示当前/目标差值和单位；无对应数据不按比例推算 |
| 技能横向列表 | 卡牌技能关联 + SkillResource + 技能阶数定义 | SkillResource已有名称、冷却、前后摇、效果等；正式关联、展示包装、图标、各阶解锁等级及效果仍缺。当前CardSkillDetailQuery只正式支持AUTO_ATTACK普攻 | ScrollList复用条目；已解锁/锁定底框、独立锁图；锁定仍可查看 |
| 成长阶段列表 | 卡牌成长阶段定义或由正式等级解锁配置推导的统一业务结果 | 需明确每项阈值、内容、排序和来源；若只是等级带来的解锁/属性变化，不新增可领取奖励和领取存档。是否存在真实奖励业务须另有规则 | 仅已获得黄/未获得蓝，不标当前，不自行发奖励 |
| 实际培养材料 | CardLevelResource目标等级成本 + ItemResource + InventoryModel | 成本与余额已有；材料图标需补，已核实3101.IconId=0；extraCosts当前预留。不固定显示三种材料 | 渲染业务返回的1–3项，未用槽隐藏；超过设计容量显式报告，不截断成本 |
| 底部功能标签 | 当前已实现的视图定义 | 当前只有升级；无需为未知功能新建通用功能表。未来有配置驱动或开放条件需求时再接现有功能框架 | 横向列表；选中视图状态由页面管理 |

## 2. 配置层的补充建议

遵循现有Luban源表→生成代码→配置加载流程，不直接手改生成的Resource.cs。下列是数据关系建议，落表前核对现有Bean与资源索引，避免重复表。

1. **展示资源映射**：种族→培养背景；品质→台座；技能包装→标题底板；解锁状态→技能底框及锁图。属于表现资源，不能夹带解锁门槛/消耗规则。固定且共用的少量状态图也可采用Prefab引用，不必每个Sprite都新建配置表。
2. **卡牌职业及克制数据**：复用已有CardResource种族与身份；补职业关联、关系定义。先确认克制是展示还是实际战斗规则，保持同一来源。
3. **技能定义与卡牌关联**：稳定skillId、底层Active/Passive、展示Basic/Active/Ultimate/Passive、图标关联、显示顺序、逐阶解锁等级及完整效果。不要用数组位置代替包装，不把旧触发枚举当作底层技能分类。
4. **阶段展示数据**：优先引用已定义的等级解锁和成长效果，只有不能推导的独立描述才单独配置；不能把文案再复制成第二套权威数值。
5. **属性覆盖与战力**：补现有成长/战斗表的数据覆盖；战力先确定规则，查询接口再实现，不新增猜测公式。材料正式IconId及资源引用单独补齐。

技能规则已确认：三种主动包装无释放消耗；间隔读配置，不硬编码主动/大招一定大于普攻。技能随卡牌等级自动解锁，高阶完整替换低阶，不叠加；不增加技能解锁扣费或独立技能等级存档。

## 3. 业务层复用与新增边界

| 能力 | 当前状态 | 接入方式 |
|---|---|---|
| 成长资格与成本 | 已实现 | CardCollectionControl.ins.model.GetState(cardId) |
| 解锁/升级提交 | 已实现 | TryUpgrade(cardId, expectedLevel, expectedRevision, out reason)，一次点击一次提交 |
| 唯一材料余额 | 已实现 | PlayerProgressControl.ins.Inventory及其InventoryModel；不建培养页钱包 |
| 等级与扣料联合保存 | 已实现 | PlayerProgressModel候选快照Commit；保存成功才更新内存并通知；失败两者不变 |
| 更新通知 | 已实现 | CardCollectionModel.Changed及共享进度提交通知；成对订阅/注销，避免同一事务重复刷新 |
| 技能详情窗口 | ④已实现 | await CardSkillDetailControl.OpenAsync(cardId, slot, skillId, onClosed)；离页Close；同一培养页实例恢复 |
| 完整培养展示查询 | 建议补充，未实现 | 一个只读Cultivation展示快照，组合身份、成长、属性比较、技能、阶段、材料及缺项；不拥有另一份余额/等级 |
| 完整技能状态查询 | 需要补充，当前仅普攻查询 | 培养页和④共用同一关联/阶数查询，统一最高生效阶和锁定状态；不要在两个View各写一遍规则 |
| 打开培养页及来源上下文 | 待界面接入 | 严格校验cardId/来源序列，保留列表快照及返回上下文；不能静默跳到第一张 |

建议展示快照按职责拆为：基础身份、CardGrowthStateVO、属性比较行、技能条目、成长阶段行、材料展示行、missing列表。它只聚合已有业务和配置，不引入第二个成长Model。接口与最终类名需按正式工程编码规范落地。

## 4. 页面状态不进配置表、不进玩家成长存档

- 当前cardId、进入时orderedCardIds、来源类型及返回回调。
- 来源筛选/排序/滚动快照；本页技能和阶段滚动位置、选中功能标签。
- 异步图片请求版本、弹窗打开版本、升级处理中标记、关闭状态及必要焦点。
- 返回回调仅一次；技能详情关闭后保留当前实例和卡牌。切卡/关闭时取消过期异步结果。

持久化仍只有已定义的玩家业务状态。新UI不增加owned、canUpgrade、技能是否已解锁等可从等级/配置推导的重复存档字段。

## 5. 建议落地顺序与检查

1. 先固定“现有可复用接口 + 缺项清单”，完成不依赖数值的结构工作。
2. 补卡牌/技能关联、技能阶数与图标、种族背景/品质台座映射、材料图标；属性覆盖、职业/克制、阶段和战力按正式数据交付。
3. 完成共用只读查询，再接培养View与④详情，不把规则写入Panel。
4. 缺数据时区分未配置与未解锁，不能用锁图掩盖未配置。结构可继续制作，但完整真实内容验收需等正式数据覆盖。
5. 验证外键存在、逐卡目标等级连续、阶数/解锁阈值合法且有稳定顺序、图标与资源可加载、前后属性取同一等级快照、主培养与技能详情状态一致。
6. 隔离存档验证未拥有/可解锁/材料不足/可升级/满级/过期revision/重复点击/保存失败/重载；验证来源顺序首尾不循环、返回恢复及技能弹窗遮挡和关闭恢复。

## 6. 核查中发现的文档差异
