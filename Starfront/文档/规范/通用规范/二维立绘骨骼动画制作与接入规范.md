# 二维立绘骨骼动画制作与接入规范

状态：现行，R8，2026-11-13。确认来源：[专项会话](codex://threads/01a1cdbe-7e4b-7643-b753-7ca4254c0f94)用户要求“把这些整理进正式规范”，明确通用制作要求与每个角色参数清单分开，涵盖尺寸、锚点、骨骼、动作和验收，禁止把本次试样参数推广为所有角色标准。

## 一、范围与资料归属

- 本文管理二维立绘的骨骼、网格与权重制作，以及展示接入的通用契约。单图蒙皮、拆件蒙皮须在角色清单中明确。当前项目采用Unity官方2D Animation技术路线；不依赖Spine许可。引擎与包的具体版本、渲染管线写入每批交付记录，不把试点版本冻结为跨项目规则。
- 名称为“二维骨骼蒙皮动画”；单张图片的微动可称“单图网格蒙皮待机动画”，待机动作语义为Idle。连续蒙皮没有固定PNG帧数要求；采集视频或PNG用于证据时，采样数量不等于动作本身帧数。
- 通用要求仅在本文维护；逐角色、逐版本、逐用途的精确值在[角色参数清单](../专属规范/二维立绘骨骼动画角色参数清单.md)及其引用的角色记录维护。模板字段是制作/验收记录，不表示新增运行时配置表、业务ID或加载API。
- 卡牌展示沿用[卡组界面资源引用规范](../专属规范/卡组界面资源引用规范.md)及培养专项的既定尺寸、相对体量和承托规则；界面装配用aiui-to-ugui。立绘制作/拆件用game-art-asset-pipeline，静态生图仍遵守项目Image默认入口。战斗动作选择与时间权威继续遵守[作战单位动作表现规范](作战单位动作表现规范.md)，本规范不改变战斗规则或源方向数量。
- 单图只能变形已有像素。明显转身、抬臂或遮挡变化需评估拆件、补绘、层序与关节覆盖，不能以严重拉伸替代缺失图像。路线变化回到受影响的素材审核阶段。

本项目双界面定标入口为[卡牌立绘定标与双界面显示规范](../专属规范/卡牌立绘定标与双界面显示规范.md)：先培养静态尺寸审核，再蒙皮；1:1为设计单位契约，不推广为所有项目或战斗世界单位。

## 制作准入：静态形象与锚点先确认

制作蒙皮动画前，角色静态立绘形象与锚点位置必须已经确定，并有可追溯的批准版本。角色参数清单登记静态图路径/版本、形象确认依据，以及锚点语义、坐标和确认依据。任一项未确定时，先完成静态形象或锚点确认，不进入拆件、骨架绑定、网格权重与动作制作，不得靠动画试做反推或默认冻结角色形象与锚点。

已确定的静态形象与语义锚点作为制作基准。后续改变形象、构图、画布或锚点时，先确认受影响的新基准，再复核拆件映射、绑定、动作及使用端。动画补绘限于获准的运动遮挡补全，不自行改角色设计。本条依据2026-11-12用户明确补充；角色数值各自登记。

## 已验收动画的增量兼容检查（SKIN-INCREMENTAL-01/R1）

2026-11-16用户确认：已有角色形象、蒙皮与动作的验收保持原批准范围；界面接入变更只做必要兼容检查，不能自动扩大为重做或重复人审，也不能无依据阻塞其他已获准角色的制作。

1. 先记录实际差异：源图/画布/Pivot、骨架/权重、动作曲线、特效挂点、显示映射、加载与生命周期分别判断。沿用未受影响的已通过证据；不能因进入新阶段、换会话或更改UI尺寸而重置旧验收。
2. 仅尺寸、画布留白、Pivot换算或UI映射变化时，核验静动态尺度与落点一致、必要动作极值/切换不跳位及受影响挂点/裁切。加载或生命周期未变且无新异常时不机械重跑完整门控/回收套件；有变化或故障证据时补对应检查。源构图、骨架、权重或动作本身变化则扩大到实际受影响的动作及使用端，不免除必要技术回归。
3. 区分兼容检查、动作制作和用户视觉验收。按已批准基准能自主核验的兼容修复由专项完成；新动作、新外观取舍、实际改变已批准效果或约定的完整功能阶段才交相应人审，不重复提审未变的旧动作。
4. 发现真实不兼容时列出缺陷、影响范围、证据及修复归属；仅阻塞依赖该问题的接入分支。其他角色已有制作授权且输入齐备时继续，不把旧角色的无关复测作为其前置条件。

职责与移交流程见[项目规划与统筹职责规范](../专属规范/项目规划与统筹职责规范.md)“UI与角色资源制作职责边界”及“常规卡牌增量统一接入”：同契约常规增量不逐页派工，统一接入方自检后合并交用户验收。本节不将旧动作通过扩为新代码已验证，也不授权跳过真实缺陷检查。

## 二、尺寸、画布与显示

1. 分开登记：源图像素宽高、Alpha可见范围及测量阈值、制作/交付画布、Unity实际导入尺寸、PPU、目标界面设计空间、显示矩形、绑定姿态的主体显示尺寸和全部动作可见范围。不得把源图尺寸、透明画布与主体占幅混为一个“尺寸”。
2. 原图与导入后尺寸须实测；像素单位、Unity单位、界面设计单位及设备像素的换算写清。记录非二次幂缩放、最大纹理尺寸、压缩、MipMap等实际参数，禁止未声明的缩图或纵横非等比拉伸。PPU和骨架缩放协同管理，不能重复缩放。
3. 生产分辨率按最大实际显示需求、允许放大倍率与细节要求选取，不设所有角色统一分辨率或以放大旧小图冒充高清源图。系列需要统一画布时先批准该系列规格，不能从某张试样推导全角色标准。
4. 全动作预留变形边界和关节覆盖；禁止逐姿态自动裁边、自动居中或等高缩放。更改源画布、构图、裁切或留白后重新核对锚点、网格、权重及所有使用端。
5. 不把座台、品质光效、文字、业务徽标或地面阴影烘焙进立绘。已有共用静态源保留原身份及GUID；动画需要独立导入契约时显式登记派生原因和引用关系，遵守[资源复用规范](美术资源复用与引用管理规范.md)。

## 三、锚点与坐标契约

1. 每个角色明确锚点语义：足底支撑点、飞行/悬浮参考点或安装点，并标明承托对象。已有批准的静态锚点优先沿用，不以新蒙皮网格中心覆盖。悬浮偏移与角色体量分开。
2. 角色记录必须写出源画布、坐标原点、X/Y正向、单位，以及锚点的像素值和归一化值。以左下原点、W×H画布、边界连续坐标表示时：normalized=(x/W,y/H)；左上坐标转换为yBottom=H-yTop。若工具用像素索引中心，须明确其约定后再换算，不能混用H-y与H-1-y。
3. 分开记录Sprite Pivot、外部逻辑/展示根节点、根骨骼、支撑骨骼和挂点。推荐逻辑根负责定位，视觉/骨骼子节点负责形变；不同点的偏移映射须显式记录，不能默认它们天然重合。
4. 原地待机保持外部语义定位点不漂移，脚部支撑区保持稳定。悬浮角色可让本体围绕参考点运动，但运动范围和均值须记录。允许根运动的动作另记位移轨迹及接入责任，禁止动画暗中移动业务位置。
5. 旋转、缩放与镜像围绕规定的定位点执行。切换静态/动态、角色/动作和复用对象后保持同一语义点，不通过逐页补偿掩盖源锚点错误。不同构图须映射同一语义位置，不直接复制归一化坐标。
6. 枪口、特效、标签等挂点单独记录所属骨骼及局部变换；展示挂点不自行产生战斗命中或伤害语义。锚点诊断与干净效果分开提交；几何通过不代替落脚自然度审核。

## 四、骨骼、网格与权重

- 每角色记录骨骼稳定名称、父子关系、绑定姿态下的位置/旋转/缩放/长度、根骨骼及实际绑定Transform；坐标单位和相对父节点的关系必须明确。骨骼数按角色结构和动作需求确定，不以试样骨骼数量作为统一下限或上限。
- 记录固定区、活动区及刚性保护区。面部、装甲、武器等按材质观感限制弯曲/拉伸，接缝不断裂、不露底，前后层序与透明边缘正确。拆件需另列图片、层序、父骨骼和覆盖留量。
- 网格密度围绕真实弯曲区分配，记录实际顶点/三角形数、权重影响数和测试用途。权重索引有效、非负、总和归一；不得有空绑定、零权重孤立顶点、无效坐标或明显网格翻折。预算按实际用途及设备验证，不能机械复制矩形网格或全角色固定顶点数。
- 骨骼、网格和权重必须保存在可重载/可编辑资产中；重新导入、重开工程后核对数据与播放。只在内存中能动不算完成。原图、导入meta、骨骼与动画版本同时留证，修改数据不通过修改第三方包掩盖兼容问题。

## 五、动作与播放清单

**动态角色最低交付**：已纳入制作并以激活动态形象完整交付的角色，至少包含一个循环空闲动作，以及一个按角色特点明确选择的特定攻击表现动作。两者必须可独立触发/检查，特定表现单次完成后平滑回空闲；不能只用待机摆幅放大或特效闪烁冒充第二动作。攻击表现可为抬枪射击、咆哮等已确认内容，不自动产生伤害、音频、投射物或技能规则。未激活始终静态。原已验收单待机里程碑保留其批准范围，不冒称完整双动作交付。

此最低要求用于后续获授权角色的生产与验收，不授权现在批量制作其他角色。未交付动画的角色保留静态回退；移动/死亡/更多攻击不因模板列举而新增。每个角色在参数清单声明默认空闲、特定表现动作标识、触发/回退与未验证范围。

**卡牌页面播放策略（2026-11-12用户确认）**：未激活时，阵容与培养均显示静态立绘；激活后，阵容只循环空闲，不触发特定攻击表现；只有培养页在空闲与特定攻击表现之间自动轮换，特定动作完成后回空闲，再等待下一轮。手动预览入口同样受页面与激活门控约束。动作时长与培养空闲等待分别登记，不能把展示轮换当作战斗攻击计时。验收须分别检查阵容拒绝特定动作、培养连续两轮自动切换、离页与换卡取消及静态回退。

每个声明动作单独登记以下内容：

| 项目 | 必填内容 |
|---|---|
| 身份与用途 | actionId、名称、使用场景、对应角色/骨架版本 |
| 内容 | 活动部位、固定部位、旋转/位移/缩放幅度、曲线或相位；单位明确 |
| 时序 | 时长（注明秒或毫秒）、循环/单次、起始姿态、默认速度、完成后的保持/回退行为 |
| 连续性 | 循环接缝的姿态及运动速度连续；非循环动作的起止边界和中断规则 |
| 根与挂点 | 是否根运动、支撑点约束、挂点轨迹及允许范围 |
| 驱动 | AnimationClip/Animator/其他已说明驱动；脚本驱动记录可复现公式、相位和参数，不能冒称已交动作Clip |
| 时间与切换 | 时间来源、暂停/变速、默认动作、切换过渡、重入/随机起相位及复用重置策略 |
| 事件 | 有则列事件时间、语义和接收者；无则写无，不把视觉事件变成业务权威 |

展示用Idle以轻微呼吸/身体摆动为可选表现，具体幅度与周期逐角色确定；原地待机不得脚滑、整体漂移或让硬质部件呈橡皮感。动作在所有声明的速度及切换边界下都应检查。战斗动画使用既有业务时间；展示动画不擅自套用或改变战斗Timer策略。

### 持枪展示动作：抬枪、开火、回待机

本节适用于已要求制作上述三阶段的原地持枪展示动作；不把所有攻击动作都强制改成相同过程。通用流程规定制作方法和可观察的验收要求，角度、时长、发数、间隔、骨骼数、网格数和画布尺寸均由角色记录定义，禁止照搬已验收样件数值。

**制作接续流程**

1. **锁定基准与复用范围**：核对已批准角色、朝向、现有待机、显示尺度/足底锚点、实际消费入口和本轮动作范围。保留原图与已验收动作；先复用现有原生蒙皮、加载、UI显示和生命周期支持。仅调曲线时不重复安装包或重做接入；改变拆件/骨架/导入契约或共用代码时，才扩大到对应环节和受影响使用端回归。
2. **拆件及遮挡补全**：按运动与遮挡需要拆枪械、左右手臂、身体及必要附属件，不规定所有角色固定拆件数。尽量保留已批准原像素；补图只用于实际缺失区域，并登记来源、蒙版和对齐方法。各层记录同一语义锚点映射、绑定姿态、前后层序及关节覆盖；不逐件自动居中/拉伸。检查抬枪极值和回落中段的露底、残片、旧枪轮廓及穿插。
3. **建立可编辑骨架与权重**：脚底/支撑区固定，武器按刚性处理，双手与握点保持一致；肩、肘、躯干和头的响应服务于抬枪与后坐，不用大面积软拉伸替代关节动作。记录骨骼、绑定变换、网格/权重、握点与枪口挂点。按目标工程目录与导入策略保存多Sprite图集或独立拆件；验证实际导入、重导和Prefab引用，不为一次交付绕改共用导入规则。
4. **先明确关键姿态与三阶段时序**：对照空闲持枪、抬枪/瞄准、每次开火冲击、射击恢复、放枪中段及结束姿态。先让实际显示尺寸下的“抬枪—射击—回落”可辨，再细化节奏和特效；不能只让枪口闪烁或原地微震却称为完成抬枪。
5. **先在实际尺寸看效果，再做定向接入检查**：复用已有预览入口，检查大尺寸与小尺寸下是否都能读出动作。新增拆件显示需核层序/合批/透明/遮罩；单纯参数调整重点核动作与切换，沿用未受影响的已通过证据。视觉明显不足先返修，不以大量资源生命周期检查代替动作观感。
6. **从承诺的真实入口交验**：验证用户正在使用的正常页面可触发，而非只在独立场景或专用种子预览中生效。说明默认待机、触发方式、单次/自动演示开关及退出方法；开发预览与正式战斗触发分开。正常入口不得偷偷覆盖玩家数据。预览需相机时检查已有相机、GameView目标和输出；不以隐藏“No cameras rendering”等警告代替定位，也不擅自新增相机改变渲染架构。共享Play的停止、重开和释放遵守项目现场授权约定。

**三阶段动作契约**

| 阶段 | 制作与验收要求 |
|---|---|
| 抬枪/瞄准 | 从已批准空闲持枪姿势起动，枪口与双臂有清楚且协调的抬升，身体/头部响应适度。按角色定义达到瞄准准备状态后才开火；抬枪阶段不得提前出现本轮射击的枪焰或后坐。记录抬升轴/角度/位移、曲线与准备完成时刻。 |
| 开火及恢复 | 发数与间隔按角色动作表；枪焰、枪械后坐、肩臂反应对齐。后坐有明确冲击与恢复，不能套用待机式均匀正弦摇摆替代；枪身保持刚性，手不离握点，枪焰随枪口移动。音频/抛壳/投射物仅在要求的范围制作，不能默认扩展。 |
| 放枪回待机 | 最后一发的主要后坐恢复后，按已批准节奏放枪，回到原持枪姿势并继续既有待机。起止衔接不突然跳角、缩放或换位，脚底/外部根不漂移；保留或重置待机相位须明示，不能默改已验收待机。 |

角色记录须列：阶段边界、抬枪完成/射击开始的关系、逐发时刻、放枪起点、总时长、姿态及后坐曲线、握点与枪口、结束/重入/暂停/中断规则。自动演示的重复间隔单独记录，不当成动作本体时长；展示枪焰事件不成为战斗命中或伤害权威。

### 动作中的附加视觉元素：定制帧特效与挂点

**职责与前提**：角色蒙皮负责本体姿态；动作中新增火光等视觉元素，默认制作定制透明帧动画，通过语义挂点配合播放。程序多边形不作为此类特效的默认正式视觉交付。不要求每个动作都增加特效；本体咆哮不自动扩展烟雾或能量。制作前必须已确定角色静态形象、角色锚点，以及本次保留的动作版本。角色锚点负责整体定位，特效发射锚点负责逐帧贴合，两者分别记录。

**制作和交验顺序**（前一视觉门槛明确通过后再进入下一阶段）

| 阶段 | 必交产物与审核重点 | 通过后接续 |
|---|---|---|
| 静态设计 | 特效放大效果图＋角色组合示意图。审核形态、颜色、质感、发射方向、相对尺寸、光晕与遮挡。允许多张参考，分别声明形态/大小、峰值亮度等职责及批准版本；概念重绘不替代既有角色形象或动作，也不冒称实机。 | 按批准参考展开各时间阶段，不重新设计已认可属性。 |
| 独立动态 | 有实质形态/光强变化的透明PNG序列、逐帧时长及固定发射锚点；提供独立原速播放和需要的连发节奏，保留空白间隔。慢放/逐帧另标为诊断，不能替代原速验收。审核短促感、峰值、节奏、消散及与参考一致性。 | 动态获得明确认可后才打包、接入Unity。 |
| Unity组合 | 在承诺的实际页面与显示尺寸播放完整角色动作＋特效，说明正常入口与专用隔离预览的差别。审核挂点贴合、方向/大小、同步、层级/透明/遮罩、原动作保持及结束恢复。开发预览不覆盖真实玩家数据。 | 用户确认组合后保留该版本，记录证据与未验范围；不自动批量或发布。 |

多参考之间不得静默取舍；后续只改变峰值亮度时，保留已通过的形态与尺寸约束。若新要求实际改变这些属性，重新明确受影响范围。

**序列与打包要求**

- 提交透明PNG原序列及生产源/提示词、工具版本、依赖参考和处理记录。记录真实Alpha、可见范围测量阈值、发射锚点坐标原点/单位、画布、逐帧时长及单次/循环策略；不要将审稿板背景/文字带入生产图。
- 同序列固定画布、语义发射点与尺度，不能按各帧包围框居中或等高适配。亮核、实焰与辉光范围分别可测；不得用拉长火焰或延长常亮来冒充瞬时闪光。清理透明噪声的阈值及任何校准平移需留证，不随意删去细弱光晕。
- 复用既有打包工具；检查序号/帧数、逐帧与总时长、纹理范围、透明边缘、原画布、pivot及裁剪偏移。裁剪后仍以sourceSize和偏移还原，不用裁后中心当发射点。声明调色/压缩/缩放等损失并对照，保留原PNG；有方向旋转/镜像时须相应支持和核验，不能忽略打包旋转标记。

**接入契约**

1. 每个特效登记所属角色/动作/资源、挂点名与父骨骼、局部位置/旋转、局部偏移、朝向/镜像、像素到角色和UI显示的尺度映射。附着特效随挂点更新；烟雾等需要脱离时，明确触发取样后独立运动的策略，不与附着显示混用。
2. 动作与特效共用动作时间或明确同步事件，定义每次触发、结束、重复/并发及中断规则，禁止两套无关联延时器造成错位。资源须在触发前就绪，异步失效后不迟到补播；暂停/恢复与角色同步。低帧率应检查不串发、不累积延迟回放，不能承诺所有显示帧在任意帧率下都可见。
3. 复用既有帧资源和UI显示能力，按正式资源目录的导入契约登记引用/GUID/Addressables，不为本次特效绕改共用导入器。uGUI中明确世界/骨架到同一Canvas局部坐标的转换，核对前后层级、色彩、普通Alpha或其他已声明混合、CanvasGroup与Stencil/裁切。
4. 记录资源预加载、共享持有/释放、显示实例及生成Sprite的归属。动作结束/取消、切卡、关页、激活失效或对象复用时隐藏并回收，迟到加载不回填；不得销毁其他使用者的共享资源。缺资源按已声明策略回退，不悄悄换回未批准程序火焰。
5. 沿用静动态门控与页面策略：未激活不启动特效，阵容仅空闲，培养才按既定规则切换特定表现。展示特效不新增战斗伤害、音频、投射物、业务状态或发布行为。

**专项自主验收与用户判断分开**

- 自主检查：输入批准/哈希、帧序/Alpha/时长、原画布与裁剪重建、所有声明触发及无提前/串发、挂点运动/暂停、层级/透明/遮罩、异步取消/重复开关/回收重开；原角色动作、锚点及无关资源按改动范围保护。用对应运行结果和实际画面留证，未覆盖的设备、速度或性能范围如实注明。
- 用户三阶段判断分别记录，不互相替代。独立动态通过不等于Unity组合通过，组合认可不扩大为真机或发布；既有动作已通过不重复提审。帧数、时长、尺寸、亮度与骨骼数均由独立角色记录定义，不能把本次样件定为全角色常量。

## 六、接入与交付

- **静/动态激活门控**：未激活只显示静态原图，不启动骨架/动作/特效；已激活且当前角色已有可用动画才播放声明的默认动作，无资源仍静态。消费项目权威激活状态，不以碎片足够、候选预览或能否上阵推断；不新存重复业务状态。阵容/培养共用门控，同卡激活事件无需重开，状态失效立即退静态并取消旧异步结果。攻击动作仍需明确触发，不因已激活自动新增战斗行为。新增角色资源须独立按地址共享租约，不能误用其他角色动画。

- 提交原图/拆件源、纹理导入meta、骨骼/网格/权重、可用Prefab或隔离场景、实际驱动资源/代码及角色参数记录。记录版本、来源、许可、路径/GUID、文件哈希、依赖及清晰的当前版本，预览/失败记录不混为正式资源。
- 原生SpriteSkin基于SpriteRenderer，不能把示例能播放视为普通uGUI Image已经支持蒙皮。正式界面接入另核绘制方式、排序、遮罩、CanvasGroup透明、窗口过渡、安全区与动画边界；沿用[UI功能逻辑规范](UI功能逻辑规范.md)和[运行时加载规范](运行时框架与加载规范.md)。
- 明确异步请求失效、共享资源持有/释放、关闭/池化回收、动作重置与静态回退。View不擅自销毁共用材质、纹理或骨骼数据。多实例的动作相位是否独立须声明。
- 独立示例、正式装配、真实界面运行、目标设备与构建发布分别登记。当前工作只写规范时，不自动授权角色制作、正式工程接入、存档/业务配置修改或发布。

## 七、验收与变更

1. **资料/数据自检**：尺寸与Alpha、导入尺寸、锚点换算、骨骼与权重、动作时长/循环、引用完整性及重载持久化；与当前文件版本/哈希关联。
2. **动作运行自检**：全部声明动作完整播放；原生变形缓冲实际有效、顶点确实变化且坐标有限；检查根/脚/挂点约束、循环接缝、暂停/恢复、切换/中断、镜像与速度边界。采样只是证据方法，不能以少量采样证明未覆盖的完整状态。
3. **视觉验收**：实际目标显示尺寸的干净效果、静态/动态同尺度对照，以及必要的独立锚点/骨骼诊断；核对造型辨识、面部/装甲/武器形变、脚滑、穿插、透明边缘、接缝跳变和最大动作裁切。程序通过与用户自然度判断分开。
4. **接入自检**：在实际消费入口检查层序/遮罩/透明/适配、异步切换/重复开关/回收重开、静态回退与多实例。记录实例数、设备环境、采样区间、CPU/GC/内存/绘制等实际可用指标；无已定预算不虚构“性能达标”。平台/真机检查只在相应范围交验。
5. **双动作覆盖验收**：核对空闲与特定表现均实际可播放，空闲微动/嘴型符合其语义，特定表现有已批准的蓄力、爆发或关键姿态，单次结束和中断能回空闲。角色口部张合明显时评估下颌拆件/遮挡补图和刚性保护，不把整脸橡皮拉伸当成张嘴；按完整动作和真实显示尺寸检查接缝/握持/脚底。仅参数调整复用接入，新增拆件/图集/骨架时定向补导入、纹理、蒙皮和生命周期回归。
6. **三阶段持枪动作定向验收**：程序或原生运行证据覆盖完整抬枪、全部声明发次、放枪及恢复待机，核对先准备后射击、枪口事件时刻、枪械刚性、有限顶点、脚底/根固定及起止连续。以实际显示尺寸检查握枪、关节接缝、残留轮廓、武器形变、最大抬枪/后坐/枪焰边界和放枪中段；关键姿态截图加连续播放共同证明过程，不能只交一张开火帧。触发、播放中切卡/关闭、加载途中取消、重开、共享释放按改动范围定向验证，关闭后无旧骨架/特效回填。新增分层UI显示另核无叠画、材质/色彩、CanvasGroup和Stencil/裁切。
7. **动作观感与技术结果分开**：用户判断抬枪是否明显自然、射击节奏与力度、放枪回待机及握持接缝；专项自行完成可执行的数据和运行核验，不把内部自检转给用户。记录所审角色、动作版本、正常入口和证据；已通过的待机不重复提审，新射击动作也不继承待机的视觉批准。
8. 每项写未执行/自检通过/待用户验收/用户通过或退回，附入口、证据及真人所审版本。独立角色效果认可不扩大为全部角色、精确锚点、正式uGUI或发布通过。参照[阶段性设计验证流程规范](阶段性设计验证流程规范.md)交验并接续已授权余项。
9. 修改源图构图、尺寸、锚点、骨架或驱动后，列受影响动作/用途并定向复核；不覆盖未受影响的批准，不回写只读策划源文件。
