# 战斗场景网格规范

确认日期：2026-10-18。适用于 Starfront 战斗地图、地块生成、阵营初始化、基地定位、视窗及场景示意图。与《场景管理规范》配合使用。

> 2026-10-18 补充：显示包围框已取整为107×93，尺寸/外观/程序合成以[战斗场景元素表现规范](战斗场景元素表现规范.md)为准。下文保留原正六边形几何样例；不得把原列距80与新版显示列距80.25混用。运行时尚未随本次文档更新迁移。

现行可执行显示几何入口：[标准地块几何.json](参考图/场景元素/标准地块几何.json)。下文原几何样例为历史记录，不用于重新生成当前视觉网格。

## 固定规则

- 战斗场景与顶层 UI 独立。场景负责地图、实体表现和空间输入；权威状态由 Model/Control 管理，遵守场景管理规范。
- 先用同一坐标规则生成完整六边形区域，再叠加视窗。区域只覆盖略大于视窗的局部，不铺满整个场景。
- 所有格子大小、方向一致；边缘也是完整正六边形，不为贴合视窗生成窄条、半格或变形格。运行时视窗允许裁剪画面，但不得修改地图数据。
- 初始地图采用180°旋转对称。围绕同一中心，每个敌方格必须对应己方格，中立格对应中立格；地图外轮廓、双方基地也必须对应。
- 绝对中立地块不可占领、不可改变归属。黑洞是当前视觉包装，不据此推导通行、建设、引力或伤害规则；这些玩法尚待单独定义。
- 地图坐标与归属数据是几何权威。生成式效果图仅作美术参考，不能用视觉相似代替数量、坐标、对称性验收。
- 表现对象按稳定 ID 与逻辑对象关联。视窗外的逻辑不因 View 回收而停止。

## 可复现坐标定义

示意图原点为左上角，x向右、y向下。Unity采用其他坐标方向时应统一转换，不能改变归属或对称关系。

- 使用整数加倍坐标(q,k)，q范围[-5,5]，k范围[-15,15]，只保留k-q为偶数的格子。
- 格子中心：x=1000+80q；y=1000+(h/2)k。
- 六顶点：中心+s·(cos(iπ/3),sin(iπ/3))，i=0…5。
- 旋转对应格：(-q,-k)，场景坐标对应(2000-x,2000-y)。必须用整数坐标配对，不用浮点近似猜测对应格。
- 中立条件：max(|q|, |(k-q)/2|, |(k+q)/2|)≤2。
- 非中立格：k<0或(k=0且q<0)为敌方，其余为己方。中心横线两端以旋转配对划分，不强求整条分界为水平直线。

## 验收

1. 格子坐标唯一，顶点规则一致，内部无面积重叠，无畸形边缘格。
2. 每个格子的旋转对应格存在；敌我互换，中立不变。
3. 当前配置敌我各76格、中立19格；更换地图配置后按新配置验证，不能强制沿用这些数量。
4. 基地在对应阵营的有效地块上，旋转后互相重合。
5. 视窗独立定位、尺寸准确，横向九个列中心位于初始视窗内；调整视窗不改变地图数据。
6. 地图逻辑实现时加入上述自动校验。当前坐标样例已核对数量与旋转配对，不代表Unity运行时实现已验收。
