# 卡牌配套资源规范

状态：现行；确认日期：2026-11-02。依据：用户批准将卡牌通用草案及生产端、使用端双向引用规则进规范。适用于全部卡牌；具体资产按类型选用，不把突击机甲参数提升为通用标准。流程与引用契约即日起生效；下文待确认规格未定案，规范生效不代表资源或代码已接通。

## 1. 资源契约

| 项目 | 现行规则 |
|---|---|
| 需求 | 按卡牌ID记录类型、品质、业务关联、配套清单；品质、武器行为与能力以项目规则及配置为准，不从图片推导 |
| 用途矩阵 | 每张卡逐项登记牌库、卡组、选择、详情、升级、奖励/获得、战场解锁、建筑生产、单位战斗、技能特效、摧毁/废墟；标记使用、不适用或待确认，不因列入矩阵自动新增功能 |
| 形象 | 原参考、批准形象、配色、视角、尺度统一版本；所有配套引用该版本。共同变更须集中确认，保留旧版及受影响项 |
| 卡面 | 卡面属于卡牌配套资源。所有生产、派发、接续及消费会话必须读取[牌库卡面制作与消费规格](牌库卡面制作与消费规格.md)，按锁定版本执行尺寸、切角/金属斜面、实际Alpha窗口、主体近景及UI分层；精确参数只在该专项维护，不用场景单位或整卡生图替代。其他用途独立核定 |
| 分类配套 | 单位动作、生产建筑、废墟、弹体和特效按实际玩法选用。生产关联见《卡牌与生产建筑对应规范》；朝向、镜像、阴影及底座引用各专项，不在本篇复制参数 |
| 共用组件 | 品质框、血条、生产环等优先复用，独立管理，不重复烘焙进主体 |
| 规格 | 登记源尺寸、交付画布、实际显示尺寸、可见主体尺寸、锚点、安全边距、允许缩放及裁切；动画另记帧数、时长、循环和方向。未批准数值不得当标准 |

### 卡牌碎片图标：先定框体规格，再裁取卡面（2026-11-10用户修正）

- 来源为对应卡当前已批准的CardArtResource.CardImage，通过CardResource.FragmentItemId关联实际碎片道具。先测使用端框体内沿、斜切角、描边与遮罩，确定可填充显示矩形和图标规格，再从卡面选取可辨识单位的素材。
- 按2026-11-10用户再次澄清，优先保持卡面原像素1:1：先按实际框体确定图标尺寸，再在卡面中直接截取同尺寸区域；不得先把单位全身或较大区域缩小塞入框中。当前81px开口候选对应截81×81源像素、交81×81、显示81×81设计px，只增加切角Alpha遮罩。固定64px解释及“1:1仅指方形、可任意Cover缩放”的解释均退出执行；源图尺寸不足或无法辨识时单列例外，不自动缩放。设备随整体UI缩放与素材裁取缩放分开记录。
- 当前培养页97×101材料框的内沿候选、遮罩点集和装配坐标只在[培养视觉素材规范](卡牌培养视觉素材与实际尺寸验收规范.md#材料图标与道具tips的现行来源2026-11-10)维护，待本轮组合验收；资源规范不把81px候选提升为所有用途通用尺寸。
- 保存卡牌/道具ID、源路径/尺寸/Hash、左上原点cropRect、缩放方式、输出尺寸/Hash、遮罩及实际显示矩形。不同卡按主体选取近景，保留头部或其他身份特征，不机械套同一裁切坐标；插值不增加原素材细节，清晰度不足单列。
- 图标填满内开口且服从其真实切角，框外Alpha=0；保留原框金属、发光与阴影。框体内底不透明时制作可追溯的空心显示派生件，不把图标盖到外圈上。数字、品质和Tips独立，不烘焙进图标。
- 新用途先交原比例材料格和边缘诊断，再进入Figma/Unity；资源映射由正式元数据/查询提供，不能将图片已裁出视为IconId及加载链已接通。原卡面和策划源只读。

## 2. 生产端与使用端双向引用

| 位置 | 必须维护的内容 |
|---|---|
| 生产记录 | 资源标识、卡牌ID、语义用途、使用端、规格、形象版本、资源版本、交付路径及哈希 |
| 使用端规范 | 消费哪些资源，通过什么配置入口解析，显示尺寸/裁切/安全区，品质与状态组合，加载释放、缺失处理及验收要求；引用本篇，不复制整套流程 |
| 共享使用清单 | 资源→使用端→配置入口→接入状态→验收证据；由专项更新自己的记录，共同形象变更集中确认 |
| 配置约束 | 按卡牌ID及明确配置关联解析资源，不按名称猜路径，不长期写死样例图。现有CardResource.image为已存在入口，不把规划字段写成已实现 |
| 完整性 | 接入前检查资源存在、用途匹配、规格兼容及依赖完整；缺失须显式报错。开发占位须明确标注，不静默冒充正式资源 |
| 变更同步 | 规格、引用入口或形象变更须同步受影响生产记录、使用端规范、配置及使用清单，并对受影响用途复验 |

现有战场解锁用途引用《场景管理规范》及《战斗场景元素表现规范》的卡牌章节；72×88属于现行展示样板，不代表其他用途尺寸。卡组、牌库及选择用途读取《卡组界面资源引用规范》。未实现用途先登记，不提前批量生产。

## 3. 生产与交付

| 阶段 | 交付及门槛 |
|---|---|
| 需求核对 | 配套清单、用途矩阵、双向引用表及待确认项；影响制作的业务和规格先对齐。含CardImage时按[卡面任务单模板](牌库卡面制作与消费规格.md#卡面生产任务单模板由协调任务字段承载)填写规范版本、主体与共用框体/遮罩输入及交付检查项 |
| 基准确认 | 读取原图，核验游戏视角、1:1尺度及必要镜像/锚点诊断；批准后锁定形象 |
| 分类制作 | 依赖批准基准；单位静态默认按种族整批制作和集中审核，问题单位单独修正，执行《作战单位美术资源规范》。新用途样件验证后整批展开；动画按现行动画Skill审核，不越过依赖阶段 |
| 确定性处理 | 透明提取、缩放、对齐、裁剪及命名可复现；保留源文件及处理参数 |
| 配套验收 | 检查小尺寸识别、形象一致、透明边缘、锚点、镜像挂点、动作切换及组合效果 |
| 使用端验证 | 按授权接入，逐用途验证尺寸、裁切、品质/状态、缩放、遮挡、时序、离屏恢复及清理 |
| 归档 | 正式运行资源、必要描述文件、可编辑源/制作记录、预览与证据分开；清单记录批准者、日期、结论及限制 |

验收按未验证、待审核、通过、暂通过、需修正记录；缺输入/未制作另记进度。视觉、技术检查、工程接入、运行、设备分别记录。所有标记使用的场合接通并完成适用验收，才可认定整套完成；部分交付必须列出未完成用途。程序检查不能代替用户视觉确认。
