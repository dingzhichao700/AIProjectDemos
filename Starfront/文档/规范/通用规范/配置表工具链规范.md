# 配置表工具链规范

## 必备目录与交付

工程根目录指包含 `Project` 的项目目录，不是 Unity 的 `Assets` 所在目录。

```text
工程根目录/
├─ AGENTS.md
├─ 文档/
│  ├─ 规范/                     工程规范，统一入口 README.md
│  │  ├─ 通用规范/              跨项目通用规则
│  │  └─ 专属规范/              本项目专属规则
│  └─ 配置表/                   原始 Excel 及 Luban 定义
└─ Project/
   ├─ ConfigResource/           luban.conf、Defines、导表入口
   ├─ Tools/Luban/              锁定版本的生成器及全部依赖
   ├─ Tools/Luban.lock.json     版本、运行时要求及逐文件 SHA256
   └─ Assets/
      ├─ Scripts/csharp/login/cfg/  生成的 C#
      └─ ConfigBin/                生成的数据
```

必须提供 `__beans__.xlsx`、`__enums__.xlsx`、`__tables__.xlsx`、`GMResource.xlsx`、`SettingOptionResource.xlsx`、`ConfigValueResource.xlsx`。六张表作为获准的基础输入一起维护，新增业务表按业务需求接入，不自动复制其他样例数据。GM 表数据不等于已实现其中列出的 GM 功能。

模板的 `Templates/GameFramework/RootFiles/文档/配置表` 映射到导出工程根目录；`ProjectFiles` 映射到 `Project`。Skill 仓库的 `docs` 保留为规范源，导出映射到 `文档/规范`；根目录 `AGENTS.md` 的相对文档链接必须同步转换，导出工程不再并列生成旧 `docs`。

## 工具版本与路径

- 当前锁定 Luban `4.1.0+ebdb2a55680bf1c5e77be801acaab4c541862a20`，要求 PATH 中存在 dotnet 且已安装 Microsoft.NETCore.App 8.0。Unity Luban 包不能代替命令行生成器。
- 完整分发存入 `ProjectFiles/Tools/Luban`，不得只复制 Luban.dll。升级时同步锁文件、生成代码、数据及验证结果。
- `luban.conf` 中源表目录为相对自身目录的 `../../文档/配置表`；辅助定义位于 `Defines`。
- gen_json.bat、gen_bin.bat、gen.sh 保留用户确认的原版内容，不添加包装层、参数或暂停开关。脚本须从 ConfigResource 工作目录执行，原版相对路径以该目录为基准。

## 生成入口

- `gen_json.bat`：client + json + cs-simple-json。
- `gen_bin.bat`：client + bin + cs-bin。
- 两个 BAT 各自保留完整命令和末尾 pause；输出使用脚本中的固定相对路径，不接受额外输出路径参数。
- 原版 gen.sh 使用 all + json，数据输出到 ConfigResource/output，不生成 C#；其行为与 BAT 有差异，按原版保留。
- 手动运行保留 pause，成功或报错后均可查看输出。自动化由 Tools/Invoke-LubanScript.ps1 切换工作目录、仅对本次进程重定向标准输入；不改动 BAT。原版 pause 可能覆盖退出码，自动化必须检查 Luban 完成及错误日志并在失败时终止。
- JSON 与二进制读取代码必须成套使用，不能只替换数据格式。运行时须遵循下述自动适配规则；切换格式仍须同步资源登记与构建，不能只执行 gen_bin 后直接宣称发布链路已验收。
- 不手工编辑生成代码。生成的 Tables 中所有表必须登记到配置预加载清单，并由导出时的 Addressables 扫描登记到 configData。

## 验收

- 模板静态验证检查所有必备文件及生成器锁文件中的完整性哈希。
- `Tools/Test-LubanConfiguration.ps1` 将工具和源表复制到独立临时目录，从 ConfigResource 工作目录调用原版 JSON、bin 两条 BAT；验证三张基础表非空产物、Tables.cs。
- 测试的二进制产物隔离在临时目录，不覆盖模板 JSON 基线。
- 正式导出先复制源表和工具，再实际执行 JSON 生成；生成失败即终止，不允许仅凭旧配置产物、Unity 包存在或游戏能启动判定配置工具链交付完成。
- 完整 Unity 编译和 Addressables 验证仍由正式工程导出执行，导表测试不替代这些检查。

## JSON / bytes 运行时自动适配

- 以当前生成的 `Tables` 构造函数为格式权威：`Func<string, JSONNode>` 对应 JSON，`Func<string, ByteBuf>` 对应 bytes。按精确签名选择构造函数，不依赖 `GetConstructors()[0]` 的顺序；缺失或同时出现两种签名时明确报错，不猜测格式。
- 不用手动宏、文件存在性或运行平台决定格式，不手改生成代码。反射仅用于初始化；配置业务读取继续使用强类型映射对象。
- 两种格式统一通过 `ResourceLoader → ResourceManager → Addressables` 预加载，JSON 获取 JSONNode，bytes 由 TextAsset.bytes 创建新 ByteBuf。禁止用 Application.dataPath、File.ReadAllBytes 或同步等待绕过资源加载体系。
- Login 层的 `ConfigManifest.Names` 登记 Tables 所需的全部无扩展名配置名；按检测结果请求 `.json` 或 `.bytes`，统一在 configData 组、Pack Separately。加载前核对完整清单，不能漏掉已生成的表。
- 保持登录阶段加载、有限并发、初始化任务复用及真实阶段进度。所有资源成功后再创建 Tables；失败不报告完成，释放失败批次缓存并允许重试。每次二进制初始化新建 ByteBuf，避免重用已消费的读游标。
- 反射初始化须保留原始异常，缺失或损坏数据不静默切换格式。反射涉及的 Tables 构造函数及映射类型须通过 link.xml 或等价机制保留；微信热更新程序集、AOT 元数据仍按平台规范验收。
- 切换格式时，从 ConfigResource 执行原版 gen_json.bat 或 gen_bin.bat，保持 BAT 与配置路径不变。同步生成代码与数据、刷新 Unity、重新登记 Addressables 并在需要使用构建资源时重建内容；发布时仅包含当前格式，避免旧格式重复进包。执行 BAT 不等于已完成资源构建或发布。
- 验收必须覆盖 JSON 与 bytes 两套真实生成产物的编译、代表性主键和字段读取一致性、缺失/损坏报错、失败重试、并发复用及释放后重载。隔离数据读取测试与编辑器/真机 Addressables 验收分别记录，不能互相替代。

实施状态：SpaceInfinite 已接入双格式自动适配；本次更新规范，模板运行时源码尚待单独标准化回写。模板默认导出仍为 JSON。

## 跨项目常量表

ConfigValueResource 属于模板基础表，结构与枚举、ConfigValueHelper、CfgManager 缓存清理、预加载清单和正式生成数据一起维护。模板仅保留 ID 1～8 通用示例，业务 ID 及数值由项目自行配置。详细填写规则见 [常量表配置规范.md](常量表配置规范.md)。

工具链仓库的 Tools/Test-ConfigValue.ps1 编译实际 Helper、CfgManager 和当前 JSON 映射，使用替代资源 IO 做隔离验证；不替代 Unity/真机 Addressables 验收，不自动在游戏启动时运行。
