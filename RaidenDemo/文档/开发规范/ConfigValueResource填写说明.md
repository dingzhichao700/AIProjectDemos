# 通用常量配置填写规则

2026-09-07。本文定义配置格式；类型解析与读取接口已由 ConfigValueHelper 实现。

## 字段与注册

`ConfigValueResource.xlsx` 通过 `__tables__.xlsx` 注册为 `cfgObj.ConfigValueObj`，记录类型为 `resource.ConfigValueResource`，按 `id` 索引，表模式为 `map`。

| 字段 | 声明 | 填写规则 |
|---|---|---|
| id | int | 唯一配置项 ID |
| 描述 | ## 注释列 | 用途或测试意图，不导出 |
| type | ConfigValueType | 普通、列表、Map |
| valueType | ConfigValueFormat | 字符串、整数、浮点数；所有结构均需填写 |
| content | string | 原始文本；在 Excel 中按文本填写，避免自动转换、丢失前导零或精度 |

普通值由 valueType 决定类型；列表的所有元素、Map 的所有值使用同一 valueType。仅支持单层、同类型集合，不支持嵌套集合或混合值类型。

## 文本语法

- 普通字符串直接保留原文，包括首尾空白；不执行集合转义解析。
- 列表用英文逗号 `,` 分隔元素。
- Map 用英文逗号分隔条目，每个条目用一个未转义的英文冒号 `:` 分隔键和值。
- Map 键固定为字符串，保留首尾空白，按大小写敏感的原文比较。`1` 是字符串键，不转换为整数。重复键报错，不覆盖已有值。
- 集合的字符串元素、Map 键和值中，使用 `\,` 表示逗号、`\:` 表示冒号、`\\` 表示反斜杠。解析时只按未转义的分隔符拆分，再还原转义；不支持的转义或末尾孤立反斜杠报错。
- 引号不是包裹语法，是普通字符串内容；不使用 CSV 引号规则。

例：字符串列表 `hello\,world,abc` 表示两个元素 `hello,world` 和 `abc`。Map `a\:b:hello\,world` 表示键 `a:b`、值 `hello,world`。

## 空值与数值

- content 完全为空：普通字符串表示空串，列表/Map 表示空集合，普通整数/浮点数报错。空白字符不等同于空内容。
- 字符串列表允许空元素，例如 `a,,b` 的中间元素为空串；空 content 专用于空列表，因此不表示“仅一个空串的列表”。
- Map 必须具有非空键；字符串值允许为空，如 `a:`。缺少键值分隔符、额外未转义冒号、空条目或尾随逗号报错。
- 数字解析允许首尾空白；整数使用十进制，可带正负号，不接受小数点或千分位。浮点数使用英文小数点，可带正负号和科学计数法，不接受千分位、NaN 或 Infinity。
- 整数对应 C# int，浮点数对应 C# float。格式错误或超出目标类型可表示范围时报错，不静默截断、不改成零、不自动升级类型。浮点数按 float 精度读取，不承诺保留文本中的小数位数。
- 整数/浮点数集合中的空元素、Map 空数值同样报错。字符串首尾空白始终保留。

## 测试数据与验证边界

现有 ID 1～8 为示例/测试数据，保留原始测试意图。ID 2 的 `2200000000` 故意超出 int 范围，应由后续类型解析测试验证报错，不能“修正”为合法值。ID 4 的 `2200000000.000` 保留原始文本，由 float 规则解析。

content 在 Luban 中仍是 string；成功导表不代表其中的整数、浮点数或集合已经通过业务类型检查。ConfigValueHelper 在首次读取时执行类型检查和解析，只缓存成功结果。属性最终值上下限是业务规则，另由具体配置项提供，不与上述类型表示范围混为一谈。

## 业务 ID 号段

| ID 范围 | 业务归属 | 说明前缀 | 当前细分 |
|---|---|---|---|
| 1000～1999 | 通用战斗规则 | 发射器_ 等 | 1000～1099 发射规则 |
| 2000～2999 | 玩家飞机 | 玩家飞机_ | 2000 基础；2100 受击；2200 复活；2300 升级；2400 失败结算 |
| 3000～3999 | 敌机与编队 | 敌机_、敌机编队_ | 3000 敌机交互；3100 编队 |
| 4000～4999 | 掉落物与补给道具 | 道具_ | 4000 拾取警告；4100 浮动文字；4200 收集移动 |
| 5000～5999 | 战斗表现参数 | 战斗表现_ | 预留 |
| 6000～6999 | 对象池与性能参数 | 对象池_ | 6000 对象池预热 |
| 7000～7999 | 资源与表现引用 | 资源_、战斗效果_ | 预留 |

ID 只表示业务归属，不编码数据类型。同一细分业务连续编号，并在下一个百位段前保留扩展空间；说明统一采用“业务前缀_具体含义（单位）”。新增业务配置前先在本表登记号段，避免不同业务交叉占用。

存在 ID 分段规则的配置表，必须将号段定义写入表头 `id` 字段的批注；号段新增或调整时，必须同步更新表头批注和填写说明。

## 代码读取与测试

静态接口：`GetInt(id)`、`GetFloat(id)`、`GetString(id)`、`GetList<T>(id)`、`GetMap<T>(id)`；集合泛型仅支持 int、float、string，返回只读集合。请求类型必须与配置一致，即使缓存命中也会校验。缓存保存在 Helper 私有静态字典中，由 CfgManager.Init/Clear 清空。

`TestControl.TestNormal()` 已启用 `TestCaseConfigs.Run()`。OpeningPanel 在配置初始化后、编辑器或 Development Build 中调用该入口。用例明确验证 ID 1～8 的预期结果，包括 ID 2 预期越界，以及类型不匹配、集合缓存复用和只读性；独立收集失败后统一报告。修改这些测试数据时应同步调整预期断言。
