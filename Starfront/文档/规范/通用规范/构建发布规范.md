# 构建与发布职责规范

- 标准化样例工程的构建发布统一由 `game-build-release` Skill 维护；当前落地微信小游戏适配，其他平台按需增加，不能套用微信策略。
- 模板生成、源码回写由 `game-framework-toolchain` 负责；构建队列适配器保留在工程内，共用调度及发布校验位于构建发布 Skill。
- 项目参数使用 `ProjectSettings/FrameworkPlatform.json`；不在通用脚本内写死项目名、CDN、AppID。生成工程的 `Tools/Build-WeChatHotUpdate.ps1` 只转发到已安装 Skill。
- “构建”只生成候选产物，“发布”部署指定候选，“构建发布”执行两者；本地生成、Git 推送、远端可用、真机验收分别报告。
- 内容更新沿用兼容底座标识；底座能力变化需重建底座。共享哈希 Bundle 不覆盖，版本目录不可变，资源可用后才更新发布指针；回退使用同底座的已验证历史版本。
- 工程根目录不擅自新增目录，产物及验证资料使用已有 build/Tools 约定。构建不隐含提交业务源码或清理历史资源。
- 当前以对话调用 Skill 运行，无需 Jenkins。完整执行契约以已安装 `game-build-release/references/构建发布规范.md` 为唯一维护源。
