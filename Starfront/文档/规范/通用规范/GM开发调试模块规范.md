# GM 开发调试模块规范

## 定位与归属

- GM 是模板必备的开发调试业务模块，代码位于 `Project/Assets/Scripts/csharp/main/gm`，编译到 Main。Foundation 和 Login 不得引用 GMControl。
- 面板位于 `Assets/Prefab/default/gm/GmPanel.prefab`，图集原图位于 `Assets/Art/atlasSource/default/gm`，图集位于 `Assets/Art/atlas/default/gm.png`。面板与图集进入已有的 `Default Local Group`，标记 `main-content`；组名不代表资源必须本地加载，沿用项目的平台策略。
- GMResource.xlsx 继续放在工程根目录 `配置表`，使用既有 Luban 结构；导出数据属于 configData，代码属于 Login 的生成配置程序集边界。不要为将 GM 界面归入 default 而移动所有配置资源。
- 字体复用模板公共字体，不复制来源工程的系统字体。界面绑定路径和运行时类型标识同时指向 Main。

## 初始化与入口

- 正式内容、Main 程序集和配置就绪后调用 `GMControl.ins.Init()`，重复初始化不重复监听。
- 鼠标/触摸入口与 Home 快捷键共用 `OpenPanel()`；尚未进入正式内容时不启用 GM。异星军团的常驻入口与构建开关遵循[窗口层级与GM入口规范](../专属规范/窗口层级与GM入口规范.md)。
- 初始化/退出归属实际正式内容生命周期。`Shutdown()`注销快捷键、关闭GM并恢复进入前的计时器倍率；不能把业务页面关闭当作正式内容退出。异星军团在MainEntry初始化，页面仅管理自己的业务命令。
- 异星军团已明确采用构建配置enableGM，默认关闭、开发测试显式开启，按钮/Home/API统一受控。旧“无生产开关”描述已被本次用户裁决替代；模板迁移状态与项目实现分开记录。

## 参数读取、提交与结果反馈（2026-11-12 用户确认）

- **缓存用途**：`GMItem`保留各指令的编辑参数，滚动刷新或重显同一指令不得恢复默认值；配置换绑/回收必须清理旧参数和监听。`paramFormat`只用于初始化，缓存只负责保留编辑状态，不能取代执行时的最终输入读取。
- **执行快照**：执行按钮及键盘提交必须走同一入口；按[UI输入契约](UI功能逻辑规范.md#wechat-text-input)完成最终文本同步，再将当前指令所属、身份有效的编辑字段合入对应序号，保留已正确保存的离屏参数，生成独立快照后调用处理器。禁止只用`onValueChanged`维护的旧缓存执行，禁止重读默认值、读取已换绑字段、或因Confirm/Complete/失焦组合重复发放。
- **业务边界**：正式道具ID、数量格式/范围、容量及其他资格由原业务处理器和正式配置校验；不能把未知ID猜成当前卡牌，不能修改库存或降低规则制造成功。使用正式发放/保存事务，保存失败维持原数量和等级，执行结果只在业务实际提交成功后报告成功。
- **具体反馈**：发放类指令成功反馈至少包含实际道具名称/ID、本次增加量及提交后的余额；失败透传可理解的真实原因，不能仅显示笼统“成功/失败”。保留可串联的触发、有效参数、处理结果日志，配合GM既有Base/Content定位版本；日志不输出凭证或无关敏感信息。提示文案不代替真实余额、刷新和持久化核验。
- **回归检查**：至少覆盖改ID/改数量、最后一次字段值变化未发通知就立即执行、滚动/回收/换绑、旧默认ID与当前实际ID分别入账、非法ID/非法数量、连续提交、保存失败不变更/恢复后可重试，以及Confirm→Complete不重复提交。核对权威余额、依赖界面即时刷新和隔离存档重读；真机按实际Base/Content验证键盘、准确增量、关闭窗口刷新及重启保持。自测、发布与用户真机验收分别登记。

当前实现/验收与限制统一见[WECHAT-GM-INPUT-R1交接](../../交接/微信GM输入与碎片反馈修复-2026-11-12.md)。修复后真机通过不等于旧故障唯一触发序列已被证明；无旧日志时须将已复现参数同步风险与历史原机根因区分。

## 时间调试

- `-` / `=` 按原 GM 档位减速/加速，`P` 暂停/恢复；输入参数期间不响应这些全局快捷键。
- 只调整 SCENE、PLAYER、ENEMY 三类 Timer，COMMON 保持运行，使 GM 界面在暂停时仍可操作。
- 暂停记录每类 Timer 的原倍率，恢复分别还原；暂停期间选择新倍率则更新恢复目标。倍率必须是大于 0 的有限数值，暂停通过独立指令表达。
- 派生项目若另有场景时间控制器，应将 GM 操作适配到其权威接口，不保留两套互相覆盖的时间状态。

## 运行版本与场景诊断

- GM 面板顶部显示 Base（底座）、Content（内容版本）、Scene（当前业务场景ID），打开时同时输出 RuntimeDiagnostics 日志。读取本次启动实际锁定的 LoadTiming.version，不用服务器最新指针或构建目录推测当前客户端版本。
- 编辑器未走热更新链路时显示 editor (local)；非编辑器缺少有效版本时显示 unknown，不伪装成正式版本。
- 当前业务通过 GMControl.SceneIdProvider 提供实际场景ID；未进入场景显示 none，退出正式内容清空提供器。不得用默认场景常量冒充当前场景，也不得让 Foundation 反向引用业务场景。
- 诊断文字复用现有公共字体；不拦截点击、不覆盖关闭按钮或命令列表。关闭重开不重复创建节点、不累计改变列表位置。
- 验收覆盖正式版本、编辑器、未知版本、无场景、场景切换、关闭重开和提供器释放；诊断信息不等于版本兼容性或真机更新已通过。
