# GM表配置规范

适用范围：采用本表结构的项目。具体业务记录由项目维护，不因规范归入通用目录而自动成为模板数据。源表、生成与加载统一遵循[配置表工具链规范](配置表工具链规范.md)和[游戏业务与配置规范](游戏业务与配置规范.md)。

整理日期：2026-10-21。本文区分填写约定与已实现能力；校验要求不代表已有自动校验工具。

## 字段

| 字段 | 含义 |
|---|---|
| id | 配置唯一 ID |
| desc | 指令显示说明 |
| content | 注册指令名称，区分大小写 |
| paramFormat | 参数默认文本列表，不是自动校验表达式 |
| paramIntro | 与参数列表等长的说明列表 |

## 配置与扩展

- `content` 与 `RegisterCommand(content, handler)` 的名称严格对应；名称区分大小写，重复注册报错，未知指令或执行异常输出具体原因，不假报成功。
- `desc` 用于指令显示；`paramFormat` 延续旧表含义，作为参数默认文本列表；`paramIntro` 为等长的参数说明列表。字段名不代表运行时自动校验公式，参数校验由处理函数负责。
- 模板仅保留五条通用指令：`log`、`timeScale`、`timePause`、`timeResume`、`closeGM`。新增业务指令同时更新源表、导出数据及注册逻辑；模块退出时注销自己注册的处理函数。
- 配置表只定义显示内容和参数，不自动产生执行能力。业务模块在正式内容就绪后注册处理函数，并在退出时注销；迁移旧接口为注册式分发时必须说明调用方式与生命周期差异，不能仅复制表记录就宣称指令已接通。
- 背包、经验、地图、武器、关卡编辑器以及测试窗口等专属指令不进入通用模板；原始 GM 表残留的这些记录已经替换。
- 指令参数由 GMItem 独立保存，列表滚动刷新不重置当前输入，回收后清空；监听按输入框替换和注销，不使用 RemoveAllListeners 清除其他模块回调。


## 校验

检查唯一 ID、指令注册匹配、参数列表长度、无参指令、非法参数及异常反馈。新增记录不等于功能已实现。模块生命周期、快捷键、Timer 和发布边界见[GM开发调试模块规范](GM开发调试模块规范.md)。
