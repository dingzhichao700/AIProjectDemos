# 卡牌立绘定标与双界面显示规范

状态：现行，PORTRAIT-NATIVE-01/R2，2026-11-16。用户确认“培养页按标准立绘1:1；阵容按概念体量缩放”，并要求先交立绘定标组合效果，批准后才改工程。规则生效不表示资源、配置或代码已迁移。

## 1. 两个界面的尺寸职责

- 培养页专注当前单位，以主体清晰、适合座台、细节可辨、不遮挡重要信息为准。每个单位独立定标；左右切卡不要求保持单位间的概念体量比例，小单位可以放大展示。
- 阵容同时展示多个上阵单位，须体现概念体量的合理大小关系：陆战队员/幽灵为小型，医疗运输机/坦克/不朽者为中型，雷兽/战列巡航舰为大型；哨兵/感染虫较小，追猎者/刺蛇略大。剩余已确认单位分类保留于逐卡参数，不向用户反复展示一套比例数字。
- 阵容根据定标立绘/蒙皮设置必要展示缩放。只有大型可占满或局部超出台面，仍须避免遮挡相邻单位、费用和铭牌。培养页不继承此限制；不得将阵容的相对体量误用为培养页缩小单位的依据。

## 2. 先定立绘，再制蒙皮

1. 保留高清原稿；按培养页实际需要确定主体大小、透明画布和语义锚点，处理得到正式定标立绘。不可反复缩小再放大，不以插值放大冒充高清。原稿不足时声明清晰度限制，补源另行处理。
2. 1:1指正式立绘1像素对应培养页1设计单位，不是设备1物理像素。整页Canvas仍正常适配屏幕。像素/PPU/引擎单位的换算由组件统一处理，不要求骨架世界坐标等于像素。
3. 保持长宽比。画布留足已声明动作的伸展空间，不能为填满画布强行放大主体。透明留白与可见主体尺寸分别记录；所有动作保持同一定位基准。
4. 地面使用足底支撑语义点，飞行/悬浮使用参考点。培养承托点由界面统一定义；必要悬浮关系体现在已批准的图像/语义锚点内，不能靠叠加旧逐卡偏移掩盖错误。迁移时保持已批准接触效果，不机械把旧补偿归零造成跳位。
5. 蒙皮基于正式定标立绘制作或迁移，绑定姿态、画布映射和锚点一致。静态→待机→特殊动作切换不改变整体展示尺寸和落点；允许局部动作自然伸展。

## 3. 显示与状态

| 页面/状态 | 显示方式 |
|---|---|
| 培养未激活 | 灰化正式静态立绘，1:1，不启动蒙皮 |
| 培养已激活且已有动画 | 蒙皮按同一标准1:1，沿用待机与角色特定动作自动轮换 |
| 培养已激活但尚未交付动画 | 原色静态立绘1:1；标明动画交付状态，不伪造动画 |
| 阵容已上阵 | 已交付动画则只播放待机，按概念体量设置展示缩放；未交付动画保留原色静态同尺度回退 |

播放资格来自现有拥有/激活状态，不改业务规则。座台、光效、铭牌与立绘独立；座台不随单位尺寸或状态缩放。异步取消、换卡、关页和资源回收沿用蒙皮接入规范。

## 4. 参数与迁移

- 角色交付记录仅维护必要参数：高清源身份、定标图片画布与可见范围、语义Pivot、蒙皮/动作映射，以及阵容展示缩放。培养不再先适配固定框后叠加逐卡倍率。
- cultivationScale及旧基准适配框属于存量迁移数据；不能将现存实现反写为新规范。cultivationOffsetX/Y及Source绑定在迁移完成前保留，批准落点映射完成后再清理重复补偿。字段删除/源表迁移属于后续工程阶段，不在本次文档变更中执行。
- 改变源图构图/画布时复核静动态映射与两个消费端；完整缩放与裁切变化分开判定，不仅以像素尺寸相等作为兼容依据。

## 5. 审核顺序与当前状态

先交培养静态组合图（原色及未激活灰化状态）→用户批准形象/占幅/落脚或悬浮→交正式定标资源并校验1:1→适配蒙皮→按概念体量检查阵容→两页运行验收。每次修改只重审受影响部分，不用程序通过代替视觉通过。

当前仅规则整理与离线静态候选，工程、正式原图、蒙皮、配置均未迁移；候选见工作区outputs/cultivation-native-size-r2。此前cultivation-concept-preview-r1将概念比例套用培养页的候选已撤回，不得实施。当前已验收蒙皮修复保持，不能据新规则擅自重做。
