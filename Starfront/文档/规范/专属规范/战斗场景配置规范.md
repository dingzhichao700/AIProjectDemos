## BattleSceneResource

一条记录描述一个场景。地块布局在明细表中配置。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int | 场景唯一 ID |
| name | string | 场景名称 |
| width、height | int | 场景范围宽高，单位为设计像素；不是格子数，也不是设备视窗尺寸 |
| originX、originY | float | 格子 (q=0,k=0) 的中心在场景内的位置，同时为当前旋转对称中心 |
| cameraCenterX、cameraCenterY | float | 初始镜头中心在场景内的位置，单位为设计像素；不使用视窗左上角，避免随设备尺寸变化产生歧义 |
| friendlyBaseQ、friendlyBaseK | int | 己方基地所在格子的整数坐标 |
| enemyBaseQ、enemyBaseK | int | 敌方基地所在格子的整数坐标 |

场景坐标原点为左上角，X 向右、Y 向下。Unity 坐标转换由表现层统一处理。
标准格子尺寸和步进引用 [标准地块几何.json](参考图/场景元素/标准地块几何.json)，不逐场景重复配置。基地建筑资源、种族、属性不在本表定义。

## BattleSceneCellResource

一条记录描述一个初始格子；运行时根据 sceneId 查询并创建。没有记录的坐标不生成格子。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int | 跨场景唯一的地块配置 ID；不等同于运行时元素 ID |
| sceneId | int | 关联 BattleSceneResource.id |
| q、k | int | 标准六边形加倍坐标；k-q 必须为偶数 |
| camp | BattleSceneCamp | 初始归属字段；已区分UNOWNED=0（未占领）与永久中立。基地及邻格初值由初始化规则确定，运行归属读取权威状态，不以永久中立代替未占领 |
| type | BattleSceneCellType | 普通 / 山体 / 水洼；决定基础通行规则 |

camp、type 下拉来自对应枚举中文别名，覆盖第4～10000行。不配置初始解锁状态；state、initialUnlocked 及原 unlocked/unlockable 字段均已移除。
所属阵营不通过贴图推导，建筑初始化独立于格子配置。基础通行规则由 type 决定，与外观独立。

## 数据填充阶段必须补齐的校验

以下为必须覆盖的校验要求；自动化覆盖范围以实际检查证据为准，不因列入规范宣称已全量实现：

- 主键唯一；场景宽高为正；所有 sceneId 引用有效。
- 同场景 (q,k) 唯一且 k-q 为偶数。
- 按现行规范检查地块布局及归属的 180° 旋转对称关系。
- 双方基地所在格子存在、阵营对应，且基地位置互为旋转对应。
- 山体、水洼为永久中立；基础通行限制由 type 决定，不配置解锁布尔值。
- 地图在场景范围内；初始镜头位置合法，设备适配与镜头边界策略由运行时实现。

## 业务边界与待核对事项

- 初始化只生成双方基地，产兵/生产及卡牌到建筑映射由各自专项维护，不混入地图明细表。
- 水洼按实际占格形状制作，锚点、深度及透明规格见元素表现规范；1002本轮静态图授权见项目交接入口，不将旧“等待帧动画”扩大为所有场景的硬性要求。
- 岩层、摆放型障碍物及背景分别遵守元素表现、主题及场景分层规范，不凭外观推导通行。

## 外观Bean及表格结构

阶段推进统一遵守[阶段性设计验证流程规范](../通用规范/阶段性设计验证流程规范.md)。

以下保留现行外观Bean字段职责；最初仅定义、未导表的阶段已归档：
- bean.BattleSceneCellCoord：q、k。
- bean.BattleSceneAppearance：resourceType、resource、layer、cells、anchor、offset。
- cells 为已有逻辑格子的绝对坐标列表；anchor 为场景内锚点格子，资源自身 pivot 对齐其中心后加显示偏移，offset 单位为设计像素（X右Y下）。
- BattleSceneResourceType：静态图片、帧动画。
- BattleSceneVisualLayer：背景、低于地面、常规地面、地面贴合、地面阴影、地面指引、高于地面、前景。不包含固定 HUD 或 LOD 信息层。

已替代的state及初始解锁字段演变见历史快照，现行字段见本篇表格。
可攻击石堆仅预留概念，不在本轮建字段或实现。主题外观不会影响通行或其他玩法规则。

### 外观列表的 Excel 布局

BattleSceneResource 的 N～T 列为 *appearances（list,bean.BattleSceneAppearance）。
第 4 行展开 resourceType、resource、layer、cells、anchor、offset；第 5 行仅在 anchor 下展开 q、k。第 6 行为中文说明，数据从第 7 行开始。
资源类型、表现层的下拉覆盖第 7～10000 行，选项从现有枚举定义生成。
每项外观使用一行，cells 保留为单元格内列表字段；坐标列表序列化遵守下节cells#sep=,契约，并用实际数据校验。
同一场景有多项外观时，只在首行填场景基础信息；数据阶段按实际记录跨度合并基础字段单元格，不预先合并空数据行。
现有 Bean 及用户修正的格式保持不变，新增枚举沿用用户调整后的块外框、字体及对齐方式。

普通格子允许地面单位通行；山体、水洼及高石堆不允许地面单位通行，飞行单位均可通过（高石堆于2026-11-02用户确认）；不据此新增高石堆枚举或改动配置结构。外观资源不改变此逻辑。可攻击石堆只作预留概念。

## 镜头缩放补充（2026-10-26，已实施）

本节替代上节“仅单触点、忽略额外触点”的输入约定。

- BattleSceneCamera集中管理表现层镜头中心、缩放、坐标转换和边界；BattleSceneView应用容器变换及视窗裁剪；BattleSceneInput识别拖动、点击、滚轮和双指手势。镜头不修改玩法状态。
- 初始与最小倍率暂定1倍，最大1.5倍；重新打开场景恢复1倍。范围集中定义于BattleSceneCamera。
- 滚轮以鼠标所在点缩放；双指捏合以两指中点缩放，同时允许中点平移。接近场景边界时以边界约束优先。
- 镜头拖动距离、格子命中和可见范围按倍率换算。背景、内容、前景同步缩放；LOD保留独立视窗容器。
- 双指手势不触发点击；所有手指释放前不恢复单指点击或拖动，避免误解锁。失焦、关闭或视窗变化清除手势。
- 用户现有Unity编辑器中已通过PlayMode回归：真实入口、滚轮、双指模拟事件、倍率上下限、焦点保持、缩放后点击、镜头边界、关闭重开及资源释放。未执行手机真机触屏验证。
- Library/battle-scene-validation-request.json可提交带唯一requestId与当前编辑器processId的定向回归请求；仅空闲GameEntrance执行，完成后返回编辑态且不关闭用户编辑器。结果为Library/battle-scene-validation-request-result.json。
