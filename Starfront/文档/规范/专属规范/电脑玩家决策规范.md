# 电脑玩家决策规范

状态：现行。确认日期：2026-10-29。依据：用户确认首版电脑自动发展方案并授权实施。具体数值以源表为准；2026-10-29用户确认本轮游戏验证通过，长期难度平衡不在本次验收范围。

## 控制身份与职责

- 阵营和控制身份独立。BattleStartResource.controlType 使用 BattlePlayerControlType（真人 HUMAN、电脑 COMPUTER）；真人 aiProfileId 必须为0，电脑必须引用有效 BattleAIProfileResource.id。
- 当前场景1001、1002均为己方真人、敌方电脑策略1。真人对手不启动电脑决策；此开关不代表联机对战已实现。
- BattleSceneModel 持有 BattleAIModel；后者只选择购买目标，通过 BattleControl.TryUnlockForCamp 进入既有 BattleUnlockModel。输入层不拥有余额、解锁或随机结果。
- 电脑使用自己真实余额、卡组、费用、概率及解锁资格，不获得额外收入，不提前抽取或窥探随机结果。兵营建成后按既有生产规则产兵；作战单位继续使用既有索敌、技能和领地规则。

## 决策与生命周期

- 首次等待3秒，之后每2秒决策一次，每次最多购买一格；长帧不补发、不积压过去的购买机会。
- 只考虑当前已揭示、所属阵营合法、未解锁、资金足够且支付后满足保留金额的格子。无候选或资金不足就等待。
- 首先需要兵营，然后需要采集站。已有采集站时，按兵营/采集站比例判断需求；达到采集站目标后偏向兵营。这里是选择偏好，不保证概率格一定产出该建筑，也不是采集站数量硬上限。
- 候选分数＝需求结果概率×需求权重＋朝敌方基地推进程度×前进权重＋可新揭示邻格比例×扩展权重。前进程度以双方基地距离归一化并限制在0～1；新揭示邻格只计本方可通行未解锁且尚未揭示格。相同分数选费用更低者，再按格子配置ID稳定排序。
- 按所属玩家Timer推进；暂停不决策、战斗结束不购买，关闭战斗解绑监听并清理状态，重开重新计时。缺失或非法策略直接报错，不静默回退。

## 策略表

源文件：[BattleAIProfileResource.xlsx](../../配置表/BattleAIProfileResource.xlsx)。注册于__tables__，正式Luban生成，Login ConfigManifest登记，configData独立打包；不修改Foundation表清单。

| 字段 | 含义 | 策略1默认值 |
|---|---|---|
| id / name | 策略ID及名称 | 1 / 首版均衡 |
| initialDelayMs | 首次延迟毫秒，≥0 | 3000 |
| decisionIntervalMs | 后续间隔毫秒，>0 | 2000 |
| targetCollectors | 采集站发展目标，≥0 | 2 |
| producersPerCollector | 每采集站对应的兵营目标，>0 | 3 |
| currencyReserve | 购买后保留余额，≥0 | 0 |
| needWeight | 需要的建筑结果概率权重 | 100 |
| forwardWeight | 前进权重 | 5 |
| expansionWeight | 揭示扩展权重 | 2 |

权重必须有限、非负且不能全零。策略仅作用于购买决策，不改变生产周期、人口上限、兵种能力或胜负规则。

## 验收边界

自动化覆盖配置引用、双方身份、资金隔离、首购/后续需求、间隔、长帧、无候选、保留金额、归属变化、结束回收和两场景多随机种子对局。实际运行验证与用户体验验收分别记录，详见[电脑玩家开发验证](../../交接/电脑玩家开发验证-2026-10-29.md)。本轮不发布小游戏、不确认AI强度平衡，不接入联机或战术指挥。
