# 阶段性设计验证流程规范

状态：已确认。确认日期：2026-10-21。适用于场景、界面、美术资产等迭代设计；不替代各专项规范。

## 每轮设计约定

1. 开始前说明本轮验证目标、输入基准、允许修改的内容、保持不变的内容及验收标准。每轮集中解决一个明确问题或一组紧密相关的问题。
2. 选择足以验证目标的最低成本产物：逻辑布局、轮廓、灰度、材质、配色、组合效果或运行样例。不是每个任务都必须经过全部阶段。
3. 有尺寸、坐标和占位要求时，先生成可复现的几何底稿及数据，再制作视觉内容；不得从生成式图片反推精确数据。
4. 可自动检查的要求通过程序验证；视觉质量由用户审核。分别记录机器检查与视觉确认，不能以其中一个代替另一个。
5. 每轮提交可直接查看的产物，并说明验证结果、未验证项和待确认内容。只有用户明确通过当前阶段后，才进入依赖该结论的下一阶段；用户直接授权跨阶段时按其指令执行。
6. 已通过的尺寸、布局、轮廓和风格成为后续约束。需要改变时明确指出变化及影响，重新验证相关部分，不借后续细化悄悄改动。
7. 未通过时从最近已通过版本修复，控制修改范围；失败稿不作为默认基准。保留版本、输入、生成或构建方式、输出与验收记录，支持复现和回退。
8. 概念通过、精确资源交付、场景组合通过、运行验证通过分别记录。局部样例不能证明全场景、所有设备或玩法平衡已通过。

## 阶段记录的最小内容

- 版本、当前阶段、目标与状态（待审核／已通过／待修正）。
- 输入基准、保持项和修改项；源文件或可复现脚本、输出路径。
- 自动检查结果、用户验收结论、尚未验证的范围。
- 下一阶段的目标及进入条件。

## 常见流程示例

- 场景：逻辑网格与障碍布局 → 地形组合效果 → 建筑与单位尺度/遮挡 → 运行验证。
- 美术：几何占位 → 灰度造型 → 材质细节 → 配色 → 独立资源与场景检查。
- 界面：信息结构 → 布局 → 视觉 → 组件资源 → 交互与适配验证。

示例不是强制流水线；按风险选择必要阶段。设定图中的校验线、标注与正式运行资源分开，精确尺寸应以数据和实测为准。

场景整体与局部的测试性绘制，还须执行[场景美术设计与验证规范](场景美术设计与验证规范.md)；具体几何与资产表现以项目专属规范为准。

## 示意图通用规范（2026-10-27确认）

- 示意图只使用简单轮廓、色块和必要标注表达结构、逻辑关系及空间关系；不加入纹理、碎石、光效等精细风格化内容。
- 明确区分逻辑边界、视觉轮廓、锚点及高度/深度；遮挡边的诊断显示须说明。遵守项目指定几何，不因表达立体感而压扁或变形逻辑轮廓。
- 示意参数与已定稿数值明确区分；需要放大时标注倍率。简单表达不免除数据准确性检查。
- 美术风格以独立视觉样件验证，不能用结构示意图代替。示意图结构通过不等于美术素材、拼接或运行时通过。
