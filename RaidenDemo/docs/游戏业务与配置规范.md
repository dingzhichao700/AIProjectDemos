## Luban 导表入口

1. 当前工程的 JSON 配置必须通过 `Project/ConfigResource/gen_json.bat` 导出。
2. 必须从 `Project/ConfigResource` 作为工作目录调用脚本。
3. 禁止绕过脚本，自行拼装、复制、推测或直接执行 Luban 命令行参数。
4. 自动化执行时，可以非交互方式处理脚本末尾的 `pause`，但不得修改脚本的参数、输出目录、生成目标或数据格式。
5. 脚本缺失、执行失败或无法满足需求时，必须先报告问题并确认脚本调整方案，不得临时改用自拟命令导表。

## Luban 配置表格式

1. 表格顶部用于定义字段、类型、说明及嵌套关系的区域统一称为“表头定义区”，其后为“数据区”。
2. 同一张表的字体和字号必须全表统一，包括表头定义区、数据区、新增列及 Bean 展开区域。
3. 表头定义区以行为单位统一样式：同一有效行的背景色、字色必须一致，Bean 展开或合并区域不得形成局部异色。
4. 单元格以列为单位统一水平、垂直对齐方式，默认均为居中；资源路径等特殊列需要例外时，必须整列统一。
5. Bean 按字段层级展开并合并父级标题；`list,Bean` 使用多行结构，字段名前加 `*`，元素字段在下一层 `##var` 行展开。合并区域只在左上角保存内容。
6. 复制合并区域格式时，禁止从合并区域的中间或末尾单元格取样；必须从相同语义区域的左上角单元格继承。字段行、说明行、子字段行和数据行应分别从同类单元格继承格式。
7. 所有有效表头行、数据行及列表延续行必须具有与原表一致的明确线框；空白预留行不作要求。
8. 修改后必须同时检查字段内容与实际格式，至少核验：背景色、字色、字体、字号、水平/垂直对齐、合并范围、线框、列宽、下拉框及文本格式；不得仅以 Luban 导表成功作为格式验收依据。

## 碰撞形状配置核验图

1. 新增或调整飞机、子弹等实体的碰撞形状后，应生成一张核验图供人工验收。
2. 核验图必须以实体原图为底图，按原图坐标与尺寸等比例叠加碰撞形状；碰撞形状使用醒目的绿色线框，不以半透明色块遮挡原画细节。
3. 核验图必须标出实体原点，并提供简短图例，明确绿色线框与原点各自代表的含义。
4. 多碰撞形状必须同时展示，并标注每个形状的用途或尺寸，确保能直观看出形状与机身可见区域的对应关系。
5. 核验图只用于配置评审与调试，不作为运行时美术资源，不得加入 Addressables。
