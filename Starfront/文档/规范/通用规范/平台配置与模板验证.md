# 平台配置与模板验证

## 模板的默认行为

默认导出为微信构建就绪工程：模板包含已锁定的 HybridCLR/微信 SDK 依赖、程序集引用、GAMEFRAMEWORK_WECHAT 宏、Login/Main 热更新列表及构建适配器。Editor 单独编译，不进入 Player。显式选择 Standalone 时关闭微信策略并移除微信专用依赖。

微信策略下，Foundation 保留在 AOT 底座，Login/Main 由 HybridCLR 编译为 DLL，通过 Addressables 远端加载。普通工程生成与微信底座导出是两个明确步骤，不因生成了 Unity 工程就声称微信发布完成。

## 生成或切换平台

Generate-GameFrameworkProject.ps1 默认 `-Platform WeChat`。AppID、bootstrapUrl、cdnRoot 可以在首次发布前补齐；模板不填案例项目参数。输出根仍由用户明确提供。导出器在当前默认编辑器目标下编译与验证资源，不负责切换 WebGL。

已有工程在关闭 Unity 后执行工程 Tools 下的 Set-GameFrameworkPlatform.ps1，显式提供 ProjectPath 和 Platform。脚本维护 UPM 依赖、程序集引用、GAMEFRAMEWORK_WECHAT 编译宏及 ProjectSettings/FrameworkPlatform.json。不要在 Unity 正在导入或构建时切换。

- bootstrapUrl：项目 bootstrap.json 的完整 HTTP(S) 地址。
- cdnRoot：本项目候选资源的本地目录，对应远端项目根；不含其他项目资源。
- appId：实际微信小游戏 AppID。
- 模板不提供真实域名、AppID、历史底座标识或机器路径。

微信依赖锁定为源项目已验证版本：HybridCLR `fd32708e7f5106f0ffa375bcfe43342ee594c1e5`，微信转换 SDK `d288776c50578926c732496882bd6ab6684c778c`。升级须重新检查平台接口与缓存集成。依赖从各自公开仓库下载，许可证及使用条件随依赖管理。

## 微信底座及内容构建

WebGL 目标切换由 game-build-release Skill 负责。首次构建需安装本机对应 Unity 的 HybridCLR 运行时，不将 HybridCLRData 或裁剪 AOT/DLL 作为模板源文件。切换后按 Tools/Framework/WeChat 菜单顺序执行：

1. Prepare Runtime：配置热更新程序集，安装项目内 HybridCLR 运行时。
2. Generate Base：生成桥接、裁剪后的 AOT 资料、Login/Main DLL、包内底座标识及候选版本状态。
3. Export Base：构建 Addressables 和微信小游戏，并写入缓存规则及候选 CDN 资源。
4. Publish Local Pointer：候选校验成功后更新本地 current/bootstrap。远端上传由部署工具负责；本菜单不提交 Git、不推送远端。

只更新兼容业务时执行 Build Content，再发布本地指针，无须 Export Base。变更 Foundation、SDK、编译设置或新增未准备好的 AOT 依赖时重新生成底座。Library 状态及底座配套 HybridCLR 资料须另行归档，不能只保留 DLL.bytes。

自动化可调用 `FrameworkWeChatBuild.RunBatch`，传入 `-frameworkAction prepare|generate|export|content|publish`；export 还需提供 `-frameworkOutput`，必须指向项目 build 下尚不存在的目录。不要附加 `-quit`，入口会在当前 requestId 完成后返回退出码。结果位于 Library/AIUI/wechat-build-result.json。

源码只维护通用平台协议和 Unity 内构建入口。CDN 上传、跨机归档和任务编排由 game-build-release Skill 维护。

## 验证入口

- Tools/Test-GameFrameworkTemplate.ps1：模板结构、程序集依赖与资源边界检查。
- `node Tools/Tests/WeChatCacheRules.test.js`：真机不可变资源白名单及可变入口排除，共 15 项。
- Tools/Test-Timer.ps1：调度、取消、重入、异常和回收等 14 项回归。
- GameFrameworkExportPipeline.ExportBaseline：隔离工程编译、绑定核验及现场 Addressables 构建。
- FrameworkTemplateValidation.RunPlayMode：隔离工程实际运行 Opening → Login → Option → Loading → Main，错误日志使验证失败；结果写入 Library/template-runtime-validation.txt。

启动验证应使用独立验证工程和独立 productName，避免读写日常工程的本地存档。微信平台还应在实际项目验证首次下载、二次缓存、兼容内容更新和 Main 延迟加载；Editor 通过不能替代真机扫码验收。
